## 模型A：44个特征（纯IMU/行为，daily）

## 一、抓挠频率/时长（8个）

| 特征 | 计算方式 | 作用 | 例子 |
|---|---|---|---|
| `event_count` | 当天事件总次数 | 次数越多越可能持续存在不适 | 今天记录到12次抓挠 → `event_count=12` |
| `event_rate_per_wear_hour` | 次数/有效佩戴小时数 | 排除佩戴时长混淆，跨天可比 | 12次÷6小时=2次/小时；另一天8次÷2小时=4次/小时，虽然原始次数更少，但换算后**这天更频繁** |
| `total_duration_min` | 当天所有事件总时长(分钟) | 跟次数互补，"多但短"vs"少但长" | 12次事件总共用了8分钟 → `total_duration_min=8` |
| `duration_rate_per_wear_hour` | 总时长/有效佩戴小时数 | 排除佩戴时长混淆，衡量"占用时间比例" | 8分钟÷6小时=1.33分钟/小时 |
| `duration_mean` | 单次事件平均时长 | 单次抓挠的典型强度 | 8分钟÷12次≈40秒/次 |
| `duration_median` | 单次事件时长中位数 | 更抗极端值的典型强度 | 12次里有1次异常长达3分钟，其余都在20-30秒，中位数≈25秒，不会被那1次拉高 |
| `max_event_duration_sec` | 当天单次最长事件时长 | 长时间抓挠红旗依据 | 那次3分钟的事件 → `max_event_duration_sec=180` |
| `duration_std` | 单次事件时长标准差 | "都差不多长"vs"忽长忽短" | 12次里11次都是20-30秒、1次3分钟 → 标准差偏大，说明有明显异常波动 |

## 二、时间分布/聚集模式（3个）

| 特征 | 计算方式 | 作用 | 例子 |
|---|---|---|---|
| `night_ratio` | 夜间(22:00-6:00)事件数/当天总事件数 | 夜间加重是过敏性皮炎常见提示 | 12次里8次发生在凌晨0-4点 → `night_ratio=0.67`，偏高，值得关注 |
| `interval_mean` | 相邻两次事件间隔均值 | 平均密集程度 | 12次事件平均每隔40分钟发生一次 |
| `interval_std` | 相邻事件间隔标准差 | 区分"持续密集"vs"偶发不规律" | A狗：12次均匀分布在一天，间隔都接近1小时(std小)；B狗：12次里10次挤在半小时内爆发，剩下2次分散(std大)——两者`event_count`一样，但`interval_std`能区分出B是"扎堆爆发" |

## 三、跨模态（1个）

| 特征 | 计算方式 | 作用 | 例子 |
|---|---|---|---|
| `sleep_disruption_count` | 已入睡≥5分钟后被抓挠打断、清醒≥3分钟，记1次 | 瘙痒严重到能打断睡眠的行为学代理指标 | 狗晚上11点入睡，凌晨2点被自己抓醒，清醒了5分钟才重新睡着 → 记1次，`sleep_disruption_count=1` |

## 四、设备/数据质量（1个）

| 特征 | 计算方式 | 作用 | 例子 |
|---|---|---|---|
| `wear_completeness_ratio` | 有效佩戴时长/目标佩戴时长(如24h) | 决定当天其他特征可不可信 | 项圈松了几次，实际有效佩戴只有10小时/目标24小时 → `wear_completeness_ratio=0.42`，偏低，模型应该对这天的其他特征打折扣 |

## 五、个体/群体背景（2个）

| 特征 | 计算方式 | 作用 | 例子 |
|---|---|---|---|
| `history_days_available` | 到当天累计了多少天历史数据 | 基线可信程度 | 狗第5天戴项圈 → `history_days_available=5`，还不够建立多数基线窗口(大部分要求至少4-10天) |
| `breed_or_size_class` | 品种/体型分组 | 不同品种正常抓挠水平本身不同 | 柯基 vs 边牧，正常抓挠频率基线可能天然不同，模型按品种分开学习"正常"是什么样 |

## 六、基线状态量（3个）

| 特征 | 计算方式 | 作用 | 例子 |
|---|---|---|---|
| `has_any_baseline` | 0/1，8组候选窗口有没有任意一组建立起来 | 告诉模型"基线判断现在能不能信" | 狗才戴了3天 → 大部分窗口都不够天数，`has_any_baseline=0`；戴了20天后 → `has_any_baseline=1` |
| `z_score_vs_self` | (今天率-30天滚动均值)/30天滚动标准差 | 标准化偏离程度 | 平时每小时0.5次，标准差0.2；今天1.3次 → z=(1.3-0.5)/0.2=4，明显异常 |
| `consecutive_days_above_baseline` | 连续几天`excl_recent14`基线比率≥2.0 | 对齐SBS"持续性"维度 | 连续5天都比基线高2倍以上 → `consecutive_days_above_baseline=5`，比单独某一天异常更值得关注 |

## 七、反复发作（2个）

| 特征 | 计算方式 | 作用 | 例子 |
|---|---|---|---|
| `flare_episode_count_90d` | 过去90天内streak连续达到3天的次数 | 捕捉反复发作模式，不依赖用户自报病史 | 过去3个月里，这只狗有过3次"连续偏高3天以上"的情况(每次之间有恢复期) → `flare_episode_count_90d=3`，提示可能是慢性反复发作类型 |
| `days_since_last_flare_end` | 距上一次发作结束的天数 | 缓解期 vs 刚发作完 | 上次发作在12天前结束 → `days_since_last_flare_end=12` |

## 八、基线比率（16个，8组窗口×2量纲）

计算逻辑统一是：**今天的次数(或时长) ÷ 某段历史窗口的中位数**，ratio>1说明比那段历史的典型水平高。8组窗口定义不同，`count`版本用事件次数算，`duration`版本用总时长(秒)算，逻辑完全一样只是分子换了。

### count版本（8个）

| 特征 | 窗口定义 | 例子 |
|---|---|---|
| `baseline_ratio_count_recent3` | 今天次数/最近3天(不含今天)中位数 | 最近3天中位数2次，今天6次 → ratio=6/2=3.0，响应最快，新狗刚戴项圈几天就能用 |
| `baseline_ratio_count_recent7` | 今天次数/最近7天(不含今天)中位数 | 最近7天中位数3次，今天8次 → ratio=8/3≈2.67 |
| `baseline_ratio_count_recent14` | 今天次数/最近14天(不含今天)中位数 | 最近14天中位数4次，今天8次 → ratio=8/4=2.0 |
| `baseline_ratio_count_recent21` | 今天次数/最近21天(不含今天)中位数 | 最近21天中位数4次，今天8次 → ratio=8/4=2.0，比14天窗口纳入更多历史，数值更稳 |
| `baseline_ratio_count_recent30` | 今天次数/最近30天(不含今天)中位数 | 最近30天中位数5次，今天8次 → ratio=8/5=1.6，长一点的窗口通常更平滑，比率没有短窗口那么剧烈 |
| `baseline_ratio_count_recent60` | 今天次数/最近60天(不含今天)中位数 | 长期稳定基线；当前合成数据历史最长60天，这一档还没有足够数据验证，实测里全是NaN，真实数据积累够天数后生效 |
| `baseline_ratio_count_excl_recent14` | 今天次数/(跳过最近7天后)再往前14天的中位数，即"第8-21天前"这段 | 最近7天可能已经在发病，如果直接用`recent14`，中位数会被这段异常拉高到6；跳过这7天看更早的14天，中位数是3(真实健康水平) → ratio=今天次数/3，比`recent14`更准确反映真实偏离。实测这组在86场景合成数据里重要性最高 |
| `baseline_ratio_count_excl_recent30` | 今天次数/(跳过最近7天后)再往前30天的中位数 | 同上逻辑，往前看的窗口更长，基线更稳但对"发病前多久算正常"这个判断要求更多历史天数 |

### duration版本（8个，跟上面8组一一对应，分子换成总时长）

| 特征 | 窗口定义 | 例子 |
|---|---|---|
| `baseline_ratio_duration_recent3` | 今天总时长/最近3天中位数 | 最近3天中位数90秒，今天270秒 → ratio=270/90=3.0 |
| `baseline_ratio_duration_recent7` | 今天总时长/最近7天中位数 | 最近7天中位数120秒，今天300秒 → ratio=300/120=2.5 |
| `baseline_ratio_duration_recent14` | 今天总时长/最近14天中位数 | 最近14天中位数150秒，今天300秒 → ratio=300/150=2.0 |
| `baseline_ratio_duration_recent21` | 今天总时长/最近21天中位数 | 最近21天中位数150秒，今天300秒 → ratio=300/150=2.0 |
| `baseline_ratio_duration_recent30` | 今天总时长/最近30天中位数 | 最近30天中位数180秒，今天300秒 → ratio=300/180≈1.67 |
| `baseline_ratio_duration_recent60` | 今天总时长/最近60天中位数 | 同count版本，当前合成数据里全是NaN，等真实长期数据 |
| `baseline_ratio_duration_excl_recent14` | 今天总时长/(跳过最近7天后)再往前14天的中位数 | 最近7天已经在发病，中位数被拉高到240秒；跳过看更早14天，中位数是100秒(真实健康水平) → ratio=今天总时长/100，更准确反映真实偏离 |
| `baseline_ratio_duration_excl_recent30` | 今天总时长/(跳过最近7天后)再往前30天的中位数 | 同上逻辑，窗口更长更稳 |

## 九、多窗口滚动统计（8个）

`event_rate_per_wear_hour`（每小时抓挠次数）在不同时间尺度上的滚动均值/标准差，跟基线比率不同——这个不是"今天vs历史"的比值，是"某个时间尺度本身的水平和波动程度"。

| 特征 | 计算方式 | 例子 |
|---|---|---|
| `rolling_mean_3d` | 过去3天`event_rate_per_wear_hour`的滚动均值 | 过去3天分别是0.5/1.2/0.9次/小时 → `rolling_mean_3d`≈0.87 |
| `rolling_mean_7d` | 过去7天的滚动均值 | 过去7天平均每小时0.8次 → `rolling_mean_7d=0.8` |
| `rolling_mean_14d` | 过去14天的滚动均值 | 过去14天平均每小时0.7次 → `rolling_mean_14d=0.7` |
| `rolling_mean_30d` | 过去30天的滚动均值 | 过去30天平均每小时0.65次 → `rolling_mean_30d=0.65`，也是`z_score_vs_self`计算时用的分母基准均值 |
| `rolling_std_3d` | 过去3天的滚动标准差 | 过去3天0.5/1.2/0.9次/小时，波动明显 → `rolling_std_3d`偏高，短期内不稳定 |
| `rolling_std_7d` | 过去7天的滚动标准差 | 过去7天有的天0.3次/小时、有的天1.5次/小时，波动很大 → `rolling_std_7d`偏高，提示这只狗最近状态不稳定 |
| `rolling_std_14d` | 过去14天的滚动标准差 | 过去14天基本都在0.6-0.9次/小时之间小幅波动 → `rolling_std_14d`较低，说明这个尺度上状态平稳 |
| `rolling_std_30d` | 过去30天的滚动标准差 | 过去30天整体稳定在0.5-0.8次/小时 → `rolling_std_30d`较低，也是`z_score_vs_self`计算时用的分母标准差 |

## 十、Stacking特征（3个）—— 模型A的预测结果，当特征喂给模型B

| 特征 | 计算方式 | 作用 | 例子 |
|---|---|---|---|
| `model_a_proba_C0` | 模型A预测"今天是C0(正常)"的概率(用GroupKFold的out-of-fold预测，不是同一份数据训练完直接predict，避免标签泄漏) | 把模型A已经学到的"今天行为严重度"判断，作为一个信息源直接喂给模型B，不用模型B从零重新学一遍 | 模型A认为今天85%概率是C0 → `model_a_proba_C0=0.85` |
| `model_a_proba_C1` | 同上，预测"是C1"的概率 | 同上 | `model_a_proba_C1=0.12` |
| `model_a_proba_C2` | 同上，预测"是C2"的概率 | 同上 | `model_a_proba_C2=0.03`（三个概率加起来=1） |

## 十一、问答特征（7个）—— 用户填纸质表后才有，对应`questionnaire_paper_form.md`

| 特征 | 计算方式 | 作用 | 例子 |
|---|---|---|---|
| `skin_redness_level` | 皮肤颜色题里"发红程度"部分，0-2三档(正常/轻微泛红/鲜红无破损) | IMU测不到皮肤本身的样子，这个是唯一直接反映"皮肤看起来怎样"的信号 | 用户选"C.明显鲜红，但还没有破皮" → `skin_redness_level=2` |

| `hair_loss_max_diameter_level` | 最大秃毛区域题，0-3四档(无/<1-2cm/2-3cm/>3cm) | 单块脱毛面积越大，皮肤暴露、失去保护的程度越严重 | 用户选"B.最大的一块很小，直径不到1-2cm" → `hair_loss_max_diameter_level=1` |
| `coat_quality_level` | 整体毛发状态题，0-3四档(光亮/油腻打结/小范围断裂/大部分干枯) | 反映毛发的整体营养/健康状态，跟长期皮肤病/慢性消耗有关 | 用户选"B.毛发有点油、容易打结" → `coat_quality_level=1` |

## 讨论过但未采纳

| 想法 | 未采纳的原因 |
|---|---|
| `weekday_weekend_ratio`（工作日vs周末抓挠率比值） | 用日历"周几"分组，在长假/调休/居家办公等场景下会系统性分组错误——不是"没有规律"，是"规律存在但被错误的分组标签测量成了错误的结果"，没有真实的家庭作息数据支撑，宁可不加 |
| `post_activity_scratch_ratio`（活动后短时间内抓挠占比） | 支撑这个特征的临床假设站不住脚：活动后抓挠可能是正常梳理，也可能是运动升温诱发瘙痒加重，两个方向相反，不确定哪个对；另外IMU分不出"跟人互动"和"自己走动"，无法验证最初想捕捉的"社交触发"这件事 |
| 动作类型聚类（挠/舔/咬/蹭细分） | 需要原始IMU波形数据，这层特征工程拿到的输入已经是离散事件(start/end/duration)，波形早就在更上游的3分类模型那里处理掉了，属于完全不同的一块工作 |
| 日类型聚类（平静日/中度/发作日） | 跟模型A本身要学的东西(C0/C1/C2分类)重复，`z_score_vs_self`/`baseline_ratio_*`已经在做类似的事 |
| 行为画像聚类（按长期行为特征给狗分群，代替/补充品种标签，用于新狗冷启动阶段的临时基线） | 概念认可，但需要真实多只狗的数据才有业务意义——现在86只都是合成场景狗，聚类出来的"群体"是编的，验证不了什么。**记录在案，等真实数据积累后再做**，不是否决，是排期靠后 |
