# 问答特征清单——从PM问答题库提取的特征，不是PM打分公式

> 来源：PM提供的Wardyn问答题库原始表格。**这份文档只提取"有哪些问题、
> 每个问题的可能取值"当作RF的输入特征，不采用原表里每个选项对应的分数
> （那是PM主观定的权重，跟SBS的权重是同一类问题）**。每个特征的真实
> 重要性/方向，应该等真实标签攒够后让模型自己学，不是预先按PM的分数
> 硬编码进特征值里。

## 1. 范围说明

PM原始题库覆盖皮肤、眼睛、口腔三大模块，是Wardyn更大的宠物健康问答体系
的一部分，不是专门给"皮肤瘙痒评估"设计的。当前skin_health项目**只关注
皮肤/瘙痒相关的问答**，眼睛、口腔模块先不纳入这份特征清单（如果以后
项目范围扩大到多器官健康评估，再单独整理）。

## 2. 触发时机（已确认）

模型A输出达到**C1及以上**（C1或C2）才触发问答，弹给用户；C0不触发。
用户不回答的兜底逻辑、以及回答后怎么算最终S，见
`two_stage_rf_architecture.md`第2.1节（包含一个需要跟产品侧确认的
兜底逻辑细节）。

这个触发规则对下面的特征清单本身没有影响——问答特征是"什么时候被填"的
问题，跟"问答本身包含哪些信息"是两件事。

## 3. 皮肤/瘙痒问答特征（提取自PM题库，去掉打分）

| 特征名（建议） | 原问题 | 取值（有序类别，从轻到重） | 备注 |
|---|---|---|---|
| `owner_reported_skin_color` | 皮肤颜色 | 正常粉色 / 轻微泛红 / 鲜红无破损 / 黑色油脂分泌 / 色素沉着 | 后三个选项不是单调严重度顺序（黑色油脂和色素沉着是不同性质的异常，不是"比鲜红更严重"），建议拆成两个特征：`skin_redness_level`（正常→轻微泛红→鲜红，3档，单调有序）+ `skin_pigment_abnormal`（有没有黑色油脂/色素沉着，类别变量，不是有序变量） |
| `owner_reported_scratch_count_bucket` | 过去24小时抓挠次数（PVAS，用户主观数） | <5 / 5-15 / 15-30 / 30-50 / >50 | **这个跟IMU算出来的`event_count`是同一件事的两个信息源**——一个是设备客观测量，一个是主人主观感受，两者**不应该二选一，都要喂给模型**：如果两者一致，互相印证提高置信度；如果差异很大（比如设备测的次数很低但主人反映很频繁），这个差异本身可能是有意义的信号（比如设备没戴好，或者主人对"抓挠"的定义跟算法不一样，或者有算法没识别到的隐蔽抓挠模式） |
| `owner_reported_scratch_duration_bucket` | 过去24小时抓挠总时长（BSAVA，用户主观） | <0(基本不抓) / 0-1h / 1-3h / 3-6h / >6h | 同上，跟IMU的`total_duration_min`是互补信号，都要保留 |
| `odor_level` | 皮肤异味 | 无异味 / 凑近能闻到 / 30-50cm可闻到 / 进屋即闻到 | IMU完全测不到的信息，纯问答特有 |
| `skin_lesion_severity` | 皮肤是否完整/有无皮损 | 完整无异常 / 单纯干燥少量皮屑 / 斑块成片皮屑 / 糜烂渗液结痂脓疱等 | IMU测不到，纯问答特有，这是最直接反映"皮肤本身状态"的一个特征（比抓挠行为更接近皮肤病本身） |
| `hair_loss_spot_count_level` | 秃毛部位分布 | 无 / 1-2个小区域 / ≥3处 / 连续成片 | IMU测不到 |
| `hair_loss_max_diameter_level` | 最大秃毛区域直径 | 无 / <1-2cm / 2-3cm / >3cm | 跟上面`hair_loss_spot_count_level`可能相关（面积大的通常也是多处），但不完全冗余（可能只有1处但面积很大，或者很多小处但单个都很小），建议都保留 |
| `coat_quality_level` | 整体毛发状态 | 光亮顺滑 / 油腻打结 / 小范围断裂稀疏 / 大部分干枯断裂 | IMU测不到 |

## 4. 跟IMU特征的关系——不是替代，是互补

上面这些问答特征里，`owner_reported_scratch_count_bucket`和
`owner_reported_scratch_duration_bucket`跟`rf_feature_spec.md`里已有的
`event_count`/`total_duration_min`是同一个现象的两个测量源（客观 vs
主观），其余（异味/皮损/秃毛/毛发质量）是IMU完全拿不到的、纯粹靠问答
才能获得的信息，这才是问答特征真正不可替代的价值所在——不是重复测量
抓挠次数，是补充IMU测不到的"皮肤本身长什么样"。

## 5. 数据缺失是常态，不是异常

问答不是每天都有（用户不一定每次都填），训练/推理时这些特征大部分时候
是缺失的，处理方式沿用`rf_feature_engineering_plan.md`里的建议：用
`HistGradientBoostingClassifier`原生支持缺失值，不需要额外插补——模型
会自然学到"问答特征缺失"本身也是一种状态（对应"这次没有问答信息，只能
靠IMU判断"），不需要特殊处理。
