# 皮肤健康评估算法方案汇报（草稿）

> 给领导看的汇总版，技术细节见文末"参考文档"链接的各份专项文档。

## 一、要解决的问题

狗狗皮肤问题（过敏、皮炎、真菌感染等）早期表现主要是**抓挠行为异常**，
但单纯"抓得多不多"不足以判断严重程度和要不要就医。现有产品设计
（PM的Wardyn题库）用的是一套**固定权重打分公式**（每个症状选项对应
一个手动设定的分数，加总得出严重度）。

算法的判断：固定权重公式没有学习、迭代能力，不同狗的正常水平差异很大
（品种、年龄、个体习惯），一套写死的分数很难同时适配所有情况。改用
**机器学习方案**：让模型从数据里自己学出权重，而不是靠人工经验预设。

## 二、总体架构：两阶段模型

```
IMU项圈数据(抓挠/睡眠/活动)
        │
        ▼
   【模型A】行为严重度分类器（每天自动跑，不需要用户做任何事）
   输出：C0(正常)/C1(需要关注)/C2(建议就医)
        │
        ├─ C0：不打扰用户
        │
        └─ C1/C2：触发问答，推给用户（纸质表，见questionnaire_paper_form.md）
                │
                ├─ 用户不填：直接给S=同档(C1→S1，C2→S2)
                │
                └─ 用户填了：走模型B
                        │
                        ▼
              【模型B】综合严重度分类器
              输入 = 模型A全部特征 + 模型A的预测结果 + 问答信息
              输出：S0/S1/S2（更完整的判断）
```

（图中的纸质问答表见
[`questionnaire_paper_form.md`](./questionnaire_paper_form.md)）

**为什么拆两个模型**：IMU数据每天都有，问答只有触发后用户填了才有（预计
填写率不会太高）。拆开能保证"模型A单独就能撑起日常判断"，没有问答数据
影响也不大；用户填了问答，模型B能再给出更完整的判断。

## 三、跟统计规则的方案的核心区别

| | 统计规则的方案 | 算法的方案 |
|---|---|---|
| 输入特征 | 几个人工挑选的症状选项，直接对应分值 | 54个特征(模型A44个+模型B新增10个)，覆盖抓挠频率/时长/聚集模式/持续性/反复发作/多窗口基线等更丰富的维度，详见[`model_ab_feature_glossary.md`](./model_ab_feature_glossary.md) |
| 权重 | 人工预设固定分值，加权公式 | 训练数据里自动学出来(HistGradientBoostingClassifier)，不是人工拍板 |
| 狗狗抓挠基线 | 单一固定窗口(21天，跳过最近7天) | 8组候选窗口(3/7/14/21/30/60天+2组"排除近期"窗口)同时喂给模型，让训练自己验证哪个窗口有效 |
| 能不能迭代 | 改分值要人工重新拍板 | 有新数据就能重新训练，持续改进 |
| 依赖用户填表程度 | 问答分数占比固定(25%×2) | 用户不填，没有问答影响也不大(模型A单独就能出结果)；填了，模型B能给出更完整的判断 |

## 四、当前进展：合成数据验证阶段

**已完成**：
- 86个合成场景（覆盖各种抓挠模式：稳定/渐变发作/骤然发作/周期性/单日
  异常等），数据可复现，代码+数据全部入库
- 模型A：44个特征，5折交叉验证宏F1 = **0.930**
  （全部特征逐一列出计算方式/业务作用/示例，见
  [`model_ab_feature_glossary.md`](./model_ab_feature_glossary.md)）
- 模型B：模型A的44个特征 + 3个stacking特征 + 7个问答特征(共54个)，
  宏F1 = **0.902**
- 44个特征逐一有计算方式/业务含义/示例说明文档，方便团队核对
  ([`model_ab_feature_glossary.md`](./model_ab_feature_glossary.md))
- 纸质版问答表已设计完成，按PM最终版题库对齐
  ([`questionnaire_paper_form.md`](./questionnaire_paper_form.md))

**需要明确的前提**：现在的F1是在**合成数据**上跑出来的，标签是我们
自己设计规则生成的，验证的是"这套机器学习流程本身能不能跑通、特征
有没有区分力"，**不代表真实世界的准确率**——真实准确率要等接入
真实狗的数据+真实兽医诊断标签之后才能给出。

## 五、下一步计划

1. 接入真实IMU数据+真实兽医评估标签，替换合成数据重新训练、验证
2. 问答表落地试用，收集真实填写率和数据质量
3. 模型A可以更早上线（不依赖问答），模型B等真实标签攒够后再上线
4. 长期方向：基于真实多狗数据做"行为画像分群"，改进个体差异较大时
   （比如新狗刚入组、历史数据不足）的基准判断
