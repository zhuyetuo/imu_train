# 特征清单（抓挠衍生特征全集）

汇总所有讨论过、可能用于皮肤评估的特征——现在实际在用的、贝叶斯模型验证用的、以后候选要加的都在这里，方便后续选特征时对照。跟 [`skin_health.md`](skin_health.md) 是互补关系：那份文档讲机制/模型本身，这份只管"有哪些特征、含义是什么、现在用没用上"。

每个特征标了**数据类型**，是为了以后选贝叶斯模型的似然分布时用——计数量适合 Negative Binomial/Poisson（参考 `bhm_scratch_count.py`），连续量适合 Normal，比例量适合 Beta 或者做 logit 变换后当 Normal 处理，二值量适合 Bernoulli/Logistic。

---

## 频率类

| 特征 | 含义 | 数据类型 |
|---|---|---|
| `event_count` | 当天抓挠事件总次数（一次连续抓挠算1次，不是每个"抓触-回摆"动作都算） | 计数 |
| `event_rate_per_wear_hour` | 每有效佩戴小时的抓挠次数——排除"戴的时间长自然次数多"这种混淆，不同天佩戴时长不一样，直接比总次数不公平 | 连续（比率） |

## 时长类

| 特征 | 含义 | 数据类型 |
|---|---|---|
| `total_duration_sec` / `total_duration_min` | 当天所有抓挠事件加起来的总时长 | 连续（非负） |
| `duration_mean` | 单次事件的平均时长 | 连续（非负） |
| `duration_median` | 单次事件时长的中位数（比均值更抗极端值干扰） | 连续（非负） |
| `duration_max` / `max_event_duration_sec` | 当天单次持续最久的一次抓挠——超过60秒触发"长时间抓挠"红旗（`LONG_SCRATCH_RED_FLAG_SEC`） | 连续（非负） |
| `duration_std` | 单次事件时长的离散程度——每次都差不多久，还是有的很短有的特别长 | 连续（非负） |

## 时间分布类

| 特征 | 含义 | 数据类型 |
|---|---|---|
| `night_ratio` | 当天抓挠事件里，发生在夜间（22:00-06:00）的占比——夜间抓挠增多常提示皮炎/过敏恶化 | 连续（0~1比例） |
| `hour_histogram` | 按小时统计的抓挠次数分布（0~23点各多少次）——比单一的夜间占比更细，能看出具体哪个时段集中 | 24维计数向量 |

## 聚集/模式类

| 特征 | 含义 | 数据类型 |
|---|---|---|
| `interval_mean` | 相邻两次抓挠事件之间的时间间隔均值 | 连续（非负） |
| `interval_std` | 相邻事件间隔的标准差——间隔小且波动小，说明事件密集扎堆发生（`validate_bayesian_skin_model.py` 里的 `interval_std_z`，代替PM"1小时≥5次"的人为阈值） | 连续（非负） |
| `cluster_count` | 用固定阈值（1小时内≥5次，`CLUSTER_EVENTS_PER_HOUR`）判定出的"聚集时段"个数——PM文档定义的版本，跟 `interval_std` 是同一概念的两种实现，一个人为二值化，一个把原始统计量直接喂给模型自己判断 | 计数 |

## 睡眠/正常行为影响类

| 特征 | 含义 | 数据类型 |
|---|---|---|
| `sleep_interrupt_count` | 因抓挠导致的睡眠中断次数（已入睡≥5分钟后被抓挠打断，清醒≥3分钟才算1次，`INTERRUPT_SLEEP_MIN_MINUTES`/`INTERRUPT_EVENT_MIN_SEC`） | 计数 |
| `sleep_interrupt`（二值） | 当天有没有发生过睡眠中断，简化成0/1（`validate_bayesian_skin_model.py` 用的版本） | 二值 |
| `activity_duration` | 当天总活动时长——来自同一个3分类模型（活动/睡觉/抓挠）的另一个类别输出 | 连续（非负） |
| `sleep_duration` | 当天总睡眠时长——同上 | 连续（非负） |

## 相对基线/趋势类

| 特征 | 含义 | 数据类型 |
|---|---|---|
| `baseline_ratio` | 当天数值相对这只狗自己历史基线的倍数 | 连续（正） |
| `baseline_delta_abs` | 相对基线的绝对增量（PM"双门槛"的另一半，配合倍数用，防止基线很小时倍数被无限放大） | 连续 |
| `rolling_mean_3d` / `7d` / `14d` / `30d` | 过去N天的滚动均值——不同窗口反映不同时间尺度（3天看急性变化，30天看慢性趋势） | 连续（非负） |
| `z_score_vs_self` | 当天数值相对这只狗自己历史分布的标准化偏离程度 | 连续 |

## 数据质量类（不是预测特征，是必须带着的元信息）

| 特征 | 含义 | 数据类型 |
|---|---|---|
| `valid_wear_hours` | 当天有效佩戴小时数——计数特征做贝叶斯建模时，通常要当"曝光量"（exposure/offset）用，不是直接当预测变量 | 连续（非负） |
| `data_quality_flag` | good/partial/insufficient——数据够不够完整、可不可信 | 类别 |
| `bootstrap_mode` | 这只狗的基线是不是还没建立（还在用绝对阈值兜底） | 二值 |

## 现状小结

| 状态 | 涉及特征 | 用在哪 |
|---|---|---|
| **SBS规则引擎已用** | 次数、时长、聚集程度(阈值版)、睡眠中断 | `scratch_burden.py`（PM加权公式） |
| **贝叶斯有序模型验证用的精简子集** | 次数、时长、夜间占比、间隔离散度、睡眠中断(二值) | `validate_bayesian_skin_model.py` 的5个 `FEATURE_NAMES` |
| **贝叶斯计数模型用的** | 仅 `scratch_count`（当天总次数），当作被建模的因变量本身，不是自变量 | `bhm_scratch_count.py` |
| **候选，还没真正用起来** | 滚动窗口多时间尺度特征、`activity_duration`/`sleep_duration`（跨类别背景特征）、`hour_histogram`、`data_quality_flag`当作曝光量用 | 等真实数据攒够、需要扩展特征集时再加 |

## 选特征时的实用建议

1. **先少后多**：现有数据量（4只狗、几周历史）下，特征堆太多会导致贝叶斯模型的 `beta` 估不稳（尤其像 `sleep_interrupt` 这种二值特征，样本少时天然比连续特征难估，已经在 `validate_bayesian_skin_model.py` 的结果里观察到）。先用少数几个信息量最大、最独立（互相相关性低）的特征跑起来，比一次性塞进十几个维度更容易验证、更容易排查问题。
2. **`valid_wear_hours` 不要直接当特征喂进 `beta`**：更标准的做法是当"曝光量"（exposure），类似 `bhm_scratch_count.py` 里事件率是按次/天建模而不是除以佩戴小时数后再建模——用 offset 的方式让模型自己学习佩戴时长和次数的关系，比我们手动算好"每小时次数"再喂进去更符合计数模型的标准做法，这个可以作为后续优化点。
3. **相关性高的特征别一起塞**：比如 `event_count` 和 `total_duration_sec` 通常强相关（次数多的日子往往时长也长），`validate_bayesian_skin_model.py` 里已经故意在合成数据里加了这种相关性——真实特征选择时要注意，同时放两个高度相关的特征，模型不好把"影响力"分清楚到底是谁的功劳，可以考虑只留一个，或者做正交化处理。
4. **`hour_histogram` 这种高维特征暂缓**：24维的按小时分布对现在的数据量来说维度太高，不如先用聚合过的 `night_ratio` 一个数代替，等数据量上来后再考虑上更精细的时间分布特征。
