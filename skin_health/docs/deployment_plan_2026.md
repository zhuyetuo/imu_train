# 狗狗皮肤评级——2026年8月~2027年2月落地方案

> 背景：影棚4只狗（8月）→ 狗场8月下旬3只 → 9月10只 → 10月20只 → 11月30只 →
> 12月50只，明年2月产品发布，11-12月要把算法这边全部定型（留1月给其他团队
> 集成/QA）。这份文档回答两个具体问题：BHM要不要做、怎么做、前期铺垫什么；
> SBS是不是一直用。结论先说：**SBS贯穿整个周期都是主力，BHM在2月发布时只
> 承担一个范围很窄、风险很低的角色（新用户冷启动辅助），不是替换SBS**——
> 时间和数据量都不支持在12月前把BHM训练成能独立扛production的主评分引擎，
> 硬上会有前面`bhm_gallery.md`已经验证出来的真实局限（比如个体噪声大的狗
> 容易被误判）在真实用户身上重演，2月发布前来不及充分验证。

## 一句话结论

**SBS一直用，从现在到2月发布、发布之后都是主评分引擎**。BHM不是要不要做的
问题，是"做多大范围"的问题——按现在的数据增长节奏，到12月能做到的、且经过
验证敢上生产的，是让BHM只负责"全新用户的头几天该给多高的初始阈值"这一件事
（替换掉现在SBS用的Whistle FIT文献兜底阈值），SBS继续负责所有狗的日常评分，
包括BHM服务过的那些新用户过了冷启动期之后。

## 为什么BHM前期铺垫比想象中更花时间（具体要做什么）

1. **历史数据要能累积，不是每次单独跑**：现在`daily_skin_report.py`每次跑
   是读当次的`_infer.json`重新算，`bhm_scratch_count.py`的合成验证也是每次
   随机生成新数据。BHM要用真实数据训练，需要一个"按狗持续累积"的存储（哪怕
   只是每只狗一个不断追加的CSV，一天一行:日期/抓挠次数/时长等特征），现在
   就要开始建，8月的数据不建现在就永久丢失了，没法回头补。
2. **品种/体型元数据要准确**：BHM的品种层需要知道每只狗的品种，如果记录不
   准（比如混血犬按哪个品种算），品种层估计会系统性跑偏。这个信息成本很低
   （狗场登记时问清楚就行），但必须现在就开始规范收集，不是9月要用的时候
   再回头补。
3. **品种分组策略要有退路**：现在4个品种各1只，狗场后续进的狗品种构成现在
   还不确定。如果最终品种非常分散（很多品种各1-2只），品种层方差没法可靠
   估计，`bhm_gallery.md`里的"部分池化"效果就发挥不出来（借不到力，因为
   同品种没有别的狗可借）。这种情况下要有退路——按体型分组（大/中/小型犬）
   代替按品种分组，体型信息比品种更容易保证同组有足够数量。这个决策点在
   9-10月就要定，不能拖到12月才发现"数据分散、模型用不了"。
4. **影子模式不能省**：`bhm_gallery.md`目前全部是合成数据验证，合成数据再
   怎么设计场景，也不能代替真实狗真实兽医评估的验证。9月开始的影子模式
   （BHM在后台跑，但不对外展示结果）是发布前唯一能积累"BHM在真实数据上到
   底准不准"这个证据的方式，没有这一步，11月的go/no-go决策就没有依据，只能
   凭感觉判断，风险很高。
5. **工程化本身要预留时间**：现在的BHM代码都是研究/验证脚本（本地跑一次
   40-60秒MCMC，手动看结果），要接入生产至少需要：定时任务（每日增量更新+
   每周完整重新拟合）、把模型参数/后验存下来供下次增量更新用（现在每次都是
   从头拟合）、失败降级逻辑（模型拟合失败/不收敛时怎么办，不能让整个评分
   服务因为MCMC没收敛就挂掉）。这部分工程量不小，如果11月才决定go，12月一
   个月未必来得及做扎实，这也是为什么建议把BHM的生产化范围限定得很窄（只做
   冷启动辅助，不是全量评分引擎）——范围越小，12月这一个月才有可能做完并
   测扎实。

## 为什么不建议这个周期内让BHM全面替换SBS

- **数据量不支持**：即便12月有50只狗，分到4-6个品种/体型组，每组也就
  8-12只，仍然是小样本，`bhm_gallery.md`里`high_variance_noisy`场景已经
  验证出的模型局限（个体噪声大的狗容易被系统性误判）在这个数据规模下大概率
  还在，没有足够数据把它训练/校准掉。
- **验证时间不够**：SBS已经从8月开始跟兽医做双盲对照，到2月有6个月的真实
  验证积累；BHM哪怕9月就开始影子模式，到2月也只有5个月，而且前几个月各品种
  狗数量还很少，真正有意义的验证窗口更短，达不到"敢完全托付给它做生产决策"
  的验证深度。
- **风险不对称**：这是宠物健康相关的评级，误报/漏报的后果比一般推荐系统
  严重，"数据不够就不要独立上生产"这个原则应该比"想尽快用上更先进的模型"
  优先级更高。SBS虽然是规则引擎，但今年已经用真实数据校准过参数，可解释性
  强，是更稳妥的生产主力。

## 2月发布时的最终形态（预期）

- **日常评分**：全部由SBS负责，用8-11月校准过的参数版本。
- **新用户冷启动（前1-3周，个人基线还没建立）**：如果11月go/no-go通过，
  用BHM给出的品种/体型层先验替代现在SBS用的Whistle FIT文献兜底阈值，理论上
  应该比"死的文献数字"更贴合国内实际狗群的抓挠水平；如果no-go，继续用现在
  的bootstrap兜底逻辑，不影响发布。
- **BHM全量替换SBS**：留作2月发布之后、用户规模和数据积累进一步增长之后的
  下一阶段目标，不在这个周期的范围内。
