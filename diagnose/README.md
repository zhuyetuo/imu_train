# 甩身体为什么被判成抓挠

```bash
python diagnose/shake_vs_scratch.py \
  --processed_dir data/processed_2026_8_11-2026_8_27_raw_missing_drop_window \
  --model results/processed_2026_8_11-2026_8_27_raw_missing_drop_window/16hz_remap_custom_3class/rf/ml_rf.pkl \
  --hz 16
```

三段各回答一个假设。**按嫌疑从大到小排**。

---

## ① 后处理里有三条规则主动把甩身体变成抓挠

这是最大嫌疑，而且**跟模型完全无关**：

1. **吞并** —— 抓挠 bout 前后 `STABLE_SHAKE_ABSORB_S`（默认 **3 秒**）内的甩身体
   窗口并进抓挠（往外扩的**累计**秒数不超过这个值）。

   > ⚠ 这条早先有 bug：判据写的是**相邻窗口之间的间隔**，而 majority 模式下
   > 相邻窗口的 zone 首尾相接、间隔**恒等于 0**，于是 `0 <= 3` 永远成立，
   > `while` 一路链式吞到底 —— **3 秒的参数把 4.5 秒的甩身体整段吞光了，
   > 而且写 0 也关不掉**（`0 <= 0` 为真）。已修，见
   > `label_service/test_shake_absorb.py`。
2. 被吞掉的窗口**从甩身体那边删掉**，不是两边都算。
3. 写时间轴时**抓挠优先** —— 抓挠能覆盖已经写上的甩身体，反过来不行。

`postprocess.py` 顶部写了这条规则的来由：「抓完常甩一下，模型也爱把抓挠的
剧烈段判成甩身体」—— **它是为了修反方向的错而加的**，现在矫枉过正了。

### 怎么验（平台上现成就能做）

同一个样本分别用**调试版**和**稳定版 v2** 跑一遍。调试版是模型逐窗口的原始
输出，**不过后处理**。

- 调试版里是甩身体、稳定版里变抓挠 → **100% 是这几条规则**
- 两个版本都判成抓挠 → 才是模型/数据的问题，看 ②③

### 怎么关

```bash
echo "STABLE_SHAKE_ABSORB_S=0" >> label_service/.env
bash label_service/up.sh -u
```

关掉之后如果又冒出一堆「抓挠被切成一段段、中间夹着甩身体」，那就是把
这条规则当初要解决的问题放回来了 —— 折中值调 1~1.5 秒。

---

## ② 标注有没有错

`②` 那段会打出**混淆矩阵**，以及「模型高置信度判甩身体、而标注是抓挠」的
窗口清单（按置信度排序，导出 CSV）。

**模型越确信、标注越可疑。** 但这不等于标注错了 —— 两类本来就像。
要确认只能回去看视频；好在按置信度排序之后，前几十个里如果真有错标很容易
一眼看出来。

同时会打出两类的样本量对比。当前数据里：

```
抓挠   2638 个窗口
甩身体  535 个窗口   ← 差 5 倍，占训练集 0.3%
```

**这个不均衡本身就足以让甩身体往抓挠上倒，不需要标注有错。**

---

## ③ 提到 25Hz 有没有用 —— **没有**

实测（抓挠 5.0Hz、甩身体 4.5Hz，60 个噪声种子，`test_resolution.py`）：

| 配置 | 频率分辨率 | 结果 |
|---|---|---|
| 16Hz / 1s | 1.00 Hz | 甩身体在 4 和 5 之间跳，跟抓挠重合 |
| **25Hz / 1s** | **1.00 Hz** | **跟 16Hz 一模一样**，照样重合 |
| 50Hz / 1s | 1.56 Hz | 反而更差（见下） |
| **16Hz / 2s** | **0.50 Hz** | **稳定分开** |

原因：

```
分辨率 = fs / nperseg，而 nperseg = fs × 窗口秒数
      → fs 约掉 → 分辨率 = 1 / 窗口秒数
```

**频率分辨率由窗口时长决定，不由采样率决定。** 提采样率抬的是 Nyquist
（能看到多高的频率），不是分辨能力。

而且 4.5 卡在格子边上，**落到哪一格由噪声决定** —— 同一个动作有时报 4Hz
有时报 5Hz，模型拿到的这一维本身就是抖的。

### 一个坑：nperseg 有上限

`src/ml/features.py:_freq_stats_1d` 里写死 `nperseg = min(len(x), 32)`。
超过 32 点就被截断，于是：

- 50Hz/1s（50 点）→ 只有 1.56Hz，**比 16Hz/1s 还差**
- 25Hz/2s（50 点）→ 只有 0.78Hz，不是 0.5Hz

**想靠加长窗口拿分辨率，得连这个上限一起放开。**

### 采样率不是完全没用

它决定能看到多高的频率。9Hz 在 16Hz 下会混叠，25Hz 下看得到。所以 ③ 里
还有一条「多少窗口贴着 Nyquist」—— 如果甩身体有相当比例压在 6Hz 以上，
那部分 16Hz 确实吃亏。

---

## 所以该动哪里

按性价比排：

1. **先关 `STABLE_SHAKE_ABSORB_S`，看现象还在不在。** 零成本，两分钟。
2. **补甩身体的数据。** 535 个窗口 / 0.3% 太少了，这是模型层面最直接的短板。
3. **窗口 1s → 2s**（同时把 `nperseg` 上限放开）。这是唯一能在频率这一维
   真正分开两类的办法，但要重训，而且窗口变长会让短促的抓挠更容易被稀释 ——
   建议先做 1、2。
4. 提采样率 **不在这个列表里** —— 对这个具体问题没用。
