狗独自在外面时，什么时候该开卫星定位

卫星定位（GNSS）是项圈上最耗电的部件之一。定时打点又费电、又打出一堆重复点。这一页的做法：平时卫星定位关着，只用一颗 3 轴加速度计判断狗是不是真的走出去了，需要时才开一次。

三种定位场景，这一页管第三种

在家

网关定位

连得上家里的网关就用网关，不开卫星。屋里卫星信号也进不来。

户外，主人在旁边

手机定位

连得上主人手机，就借手机的位置。

狗独自外出 · 网关和手机都连不上

只能靠卫星 这一页

由加速度计决定什么时候开卫星打一个点。

为什么不能定时打点

288个/天每 5 分钟打一个点
50mAh/天每 5 分钟一个点的 GNSS 耗电（估算）
13分钟/天狗场的狗一天平均只在走这么久（戴着约 23 小时）
14.5个/天智能打点（省电档）中位数

狗大部分时间在睡、在趴着、在原地转悠，这时候打的点几乎都落在同一个地方，全是浪费。真正需要追的只有它走出去的那十几二十分钟。

怎么做

① 计步|a| 去掉 1 秒慢基线；峰值 > 60 mg、两步至少隔 0.25 秒记一步。抓挠每秒 5–8 下，峰挤在一起，大部分不会被当成步子
② 在走 / 跑最近 4 秒有 5–18 步，而且节奏均匀（步间隔变异 ≤45%）
③ 持续移动最近 15 秒里至少 10 秒在走 / 跑。抖一下身、喝两口水不算
④ 打点出发 · 移动中 · 到达 · 保底，四个时机，见下图
⑤ 压徘徊打完点回传实际挪了多远：总在原地转，就把打点间隔放大，最多 4 倍

真实的一天：三档各打了多少点

这一分钟走了几秒 出发移动中 到达保底

每 5 分钟固定打点那一行是密密一排，几乎全落在狗不动的时候；智能打点都挤在它真正走动的几段里。

板上怎么接

纯整数运算、没有 malloc，一个状态结构体约 200 字节。代码在 experiments/claude_2026_11/gnss/（gnss_trigger.c / .h）。

gt_state_t st;
gt_init(&st, GT_PRESET_SAVE);              // 默认省电；App 里切档就调 gt_set_preset

// 加速度计 20 Hz 回调（单位 mg）
gt_feed(&st, ax, ay, az);

// 每秒一次
gt_reason_t r = gt_tick(&st);              // GT_DEPART / GT_MOVING / GT_ARRIVE / GT_HEARTBEAT
if (r != GT_NONE && !gateway_ok() && !phone_ok()) {
    gnss_fix_once();                        // 网关、手机都连不上才开卫星
}

// 打完点（可选）：告诉它跟上一个点实际差多远，用来压「原地徘徊」
gt_on_fix(&st, moved_m);

还没定的

  1. 每步多少米 现在按 60 cm 估。要拿真实 GNSS 轨迹标定，不同体型的狗可能要分档。
  2. 耗电 换成实际定位模组的手册数字（启动时间、电流），再算一遍。
  3. 户外数据 狗场的狗一天只走十几分钟。要补真实遛狗 / 独自外出的数据，看户外打点数和漏追距离。
  4. 喝水、抖身误开 现在靠「走出 N 米」挡；如果户外数据里还多，再加一条「步子要有向前的规律」。
