从项圈 IMU 里认出抓挠、舔、甩头、吃喝和休息

项圈里有一颗 6 轴 IMU（加速度 + 陀螺仪）。这一步的输出是一串行为事件（几点几分、抓了多久、多大把握），交给第二步皮肤评估去算“这只狗今天抓得正不正常”。核心是把抓挠找准，同时把误报压低：误报会直接把皮肤评分抬高。

流程

① 采集项圈 IMU 20 Hz，6 轴；同时录视频当“答案”
② 标注平台视频 + 波形对齐标片段；模型先给疑似片段，人来确认
③ 训练4 秒窗口、0.5 秒步长（端侧现有版本 8 秒）；按“天 × 项圈”分组 5 折，防止同一只狗同一天泄漏
④ 后处理动作门 + Viterbi 平滑，把逐窗结果连成事件
⑤ 端侧导出int8 1D-CNN，导出 C 数组进固件
⑥ 服务端XGB / CNN 推理服务，给平台打候选、给 App 复核

评估指标：窗口级、片段级、事件级

行为识别同时是两件事：逐窗分类（这 4 秒是抓挠还是活动？）和时间序列分割（抓挠从几点到几点？）。前者衡量“看得准不准”，后者衡量“切得对不对”。所以评估分三层，缺一层都会得出错误结论。

口径怎么算学术界对应产业界对应我们现在的数（4 s / 0.5 s CNN）
窗口级

片段级（宽松）

事件级（严格）

整段有重叠 0.892 · 误报 6.19 次/h · 起止误差 0.57 / 0.85 s
三者关系：窗口级是“零件”，片段级是“装配对不对”，事件级才是“用户拿到的那一串事件准不准”。同一份模型：窗口抓挠 F1 0.854 → 宽松片段 F1 0.939 → 事件 F1 0.544。后两个不矛盾：宽松口径只回答“有没有抓到”，事件口径还要求起止对、时长对、不多报。产品验收和对外承诺用事件级；宽松口径只用于跟历史版本对齐。
评估的已知局限： ① 滑窗重叠（4 s 窗 / 0.5 s 步 = 8 倍重叠），窗口之间高度相关，窗口级数字天然偏乐观，所以不作为验收线； ② 数据池是稀疏标注（每个文件只标约 0.8% 的时间）：按“标了别的类的时间”算的每小时误报是下限；事件查准则把所有预测都放进分母，落在未标时间的预测也会拉低查准，所以查准偏保守； ③ 人标边界本身有 1 秒左右误差，IoU 0.5 对 2 秒的段非常苛刻； ④ 交叉验证按“天 × 项圈”分组，但跟现场分布仍有差异（影棚争议），所以指标要按场地拆开、并配合失败样本回放。

工具参考：pyannote-metrics（Detection）、TimeEval（range-based）、dtaianomaly、tsseg-eval（WARI / SMS）、tsseg。实现：src/ml/train_v2.py 的 segment_metrics()。

测试标准、流程与方法

抓挠这类任务不能只看窗口准确率。现在按上节的三层指标组织测试，主验收是事件级；下面是从测试集构造、执行流程到通过标准的完整梳理。

1. 测试集怎么来

  • 数据：当前训练 / 测试集 2408 个 CSV（平台数据池 + 老抓挠数据 + 公开集），抓挠真值 5307 段；数据池本身 1450 个任务、45.9 小时、5551 段标注。公开狗数据 22.8 小时（Vehkaoja 2022、Marcato 2023）。
  • 切分：按 (天, 项圈) 分组做 StratifiedGroupKFold 5 折——同一天、同一只狗的数据只会出现在训练或测试一边；公开集按狗分组。这是防泄漏的关键：随机切窗口会让相邻窗口同时进训练和测试，指标虚高十几个点。
  • 窗口：只在标注段内部滑窗，不跨掉包（>0.3 s 无数据）和类别边界；短于一个窗口的段以段中心取窗、用真实原始数据补边，训练时左右挪几次做增强，验证不增强；全 0 行（蓝牙断连占位）按缺失处理。
  • 后处理：测试阶段的连续推理走平台同一份代码——动作门（静止 / 未佩戴）→ Viterbi 稳定版 → 精准版起止对齐，不另写一套评估逻辑。

4. 一次测试的流程

  1. 锁定 spec
    窗口 / 步长、轴数、类别与归并、校准系数、负例与公开集是否加入。一次只改一个变量。
  2. 提交训练
    平台「提交训练」或 train_v2.py --spec。训练中自动完成 5 折 OOF、每折留出文件连续推理、后处理、三层指标，写进训练记录。
  3. 先查异常
    某折或某场地明显塌，先查数据泄漏、类别缺失、标注异常，再谈模型。
  4. 同口径对比基线
    事件查全 / 查准 / F1、误报 / 小时、起止误差、分场地 / 分段长；不要拿宽松口径跟事件口径比。
  5. 下结论
    只认事件级；宽松口径用于跟历史版本对齐，窗口级用于排错。
  6. 失败样本回放
    TRAIN_V2_DUMP_OOF 导出逐窗预测，挑误报 / 漏报片段按 CSV 回放，确认是模型、后处理还是标注问题。
测试方法本身的不足（要补的）： ① 没有冻结盲测集——所有实验都在同一套 5 折上挑，存在“实验级过拟合”，数字偏乐观。建议按场地 + 周留一份 lockbox，只在最终候选上跑一次； ② 稀疏标注：未标时间不计误报（误报是下限），但事件查准把所有预测放进分母（查准偏保守）； ③ 人标边界约 1 秒误差，IoU 0.5 对 2 秒的段非常苛刻； ④ 影棚的交叉验证与现场反馈矛盾，说明测试分布和现场仍有差异，需要真实数据回放和现场 A/B； ⑤ 甩头 / 抖身只有约 170 段，指标方差大，不能按抓挠的标准要求它。

数据切分：窗口大小、步长与输出方式

时间序列分类 / 分割的第一道设计选择是：窗口多大、隔多久切一次、一个窗口输出一个标签还是一串标签。它同时决定模型能看到多少上下文、事件边界能对多准、端侧算多少、延迟多大。窗口和步长不是超参数里最显眼的，但往往比换模型更影响结果。

1. 学术界与产业界的常见做法

维度学术界产业界
窗口 / 步长滑窗分类（many-to-one）是 HAR 事实标准：UCI HAR 2.56 s / 50 Hz、50% 重叠；多数工作 1–5 s 窗、50–75% 重叠。经验是窗口至少覆盖 1–2 个动作周期，再在验证集上扫。
分割任务用逐点输出（many-to-many）：1D U-Net、TCN、MS-TCN 等，整个序列进、每个点出类别。		睡眠分期固定 30 s 一个 epoch（AASM 标准）；活动识别 / 手环一般 1–5 s 窗、50% 重叠；心电按 beat 或 10 s 条带；癫痫 / 跌倒 1–4 s 窗。窗口通常由 RAM / 算力 / 功耗倒推，不是纯效果最优。
输出方式能拿到逐点标签时倾向 many-to-many，边界由模型直接给；只有段级标签时用 many-to-one + 后处理。绝大多数是 many-to-one（每窗一个判决）+ 后处理（中值滤波、最短持续时间、间隔合并、滞回阈值），因为它最省算力、最好移植。
多尺度Inception 式多核并行（k=3/5/7）、空洞卷积扩大感受野、多窗口集成 / 双流（短窗管瞬态、长窗管持续动作）、级联（便宜门控 → 细分类）。资源允许时用多核卷积或双流；更多是「一个窗口 + 强后处理」，因为每多一个分支就多一份 RAM 和功耗。
验收窗口级 F1 用来比方法；事件 / 分割质量另算（IoU、range-based、WARI / SMS）。直接看事件级：episode 灵敏度、每天误报、检测延迟。

机制：窗口越长，模型看到的上下文越多、判决越稳，但事件边界被平滑掉的范围也越大——4 s 窗理论上要补 (窗−步)/2 ≈ 1.75 s 的中心偏差，精准版对齐后实测中位起止误差仍有 0.57 / 0.85 s；短段（2–3 s）因此很难过 IoU 0.5。窗口越短，边界越准、延迟越低，但抓挠的节律和“是否连续在抓”的上下文不够，且同样时长要算的窗口数成倍增加、误报更碎。

4. 多尺寸（multi-scale）

常见做法有四类：① 同一层并行不同卷积核（Inception，k=3/5/7 同时看快慢变化）；② 双流输入，短窗和长窗各一个编码器再融合；③ 层级 / 金字塔结构，深层看长上下文、浅层保边界；④ 级联，便宜的小窗门控先筛，可疑才跑大模型。

我们试到哪：11-18 试过 FilterNet 逐点输出 + 大小窗口并行，没有变好；现在的 8 s 和 4 s 是两个独立模型，不是融合，生产里也没有多尺度。下一步真正值得试的是 4 s + 8 s 双流，或把 4 s CNN 的第一层换成 k=3/5/7 并行；但要先把端侧 RAM / 算力重算一遍。注意多尺度不是「两个窗口的预测取平均」——窗口中心要对齐、概率要重新校准、后处理常数也得跟着改。

5. many-to-many（逐点 / 逐窗输出）

是什么：输入一段序列，输出每个时间点（或每个小步长）的类别，而不是一个窗口一个标签。1D U-Net、TCN、MS-TCN 都是这一类；训练时只在有标注的位置算损失，边界由模型自己学。优点是边界准、上下文长、推理时不用重复算重叠部分；缺点是要稠密标签（我们目前只有段级）、端侧要维护流式状态、算力和内存都更大。

我们为什么没直接上：标注是段级不是逐点；端侧 RF / XGB 只支持定长窗口；int8 CNN 逐窗最省事、最好导出。现在用「滑窗 many-to-one + Viterbi + 后处理」近似 many-to-many：Viterbi 已经在相邻窗口之间加了转移约束，效果上接近序列解码，但边界精度仍受窗口长度限制。

什么时候值得做：当诊断确认瓶颈是短段边界（现在就是），且端侧算力允许。落地路径：先保持 4 s 窗口、把输出改成每 0.5 s 一个（等价于现在的步长），确认不掉点；再试更小步长或逐点，标签边界 1 s 内设「忽略带」不参与损失；最后再做 C 端流式导出。

6. 步长的机制

重叠率 = 1 − 步长 / 窗口。我们现在 87.5%，好处是样本多、事件起止平滑、后处理好接；代价是相邻窗口高度相关，有效样本量远小于窗口数，窗口级指标会偏乐观，推理时同一段信号要算 8 遍。步长还直接决定端侧功耗（0.5 s 步长 = 每秒算 2 次）和最短事件长度（最短 2 个窗 = 约 1 s）。窗口和步长要一起看：窗口决定“看多长”，步长决定“多久看一次”和“边界能细到哪”。

一句话总结：我们现在是「4 s 窗 / 0.5 s 步 / 每窗一个标签 + 后处理」——用短窗换边界精度，用重叠换平滑，用 Viterbi 近似序列解码；瓶颈是 3 s 以内的短段。下一步先扫 2 s / 3 s 窗，再考虑多尺度或逐点输出，别再单纯加大窗口。
