从项圈 IMU 里认出抓挠、舔、甩头、吃喝和休息

项圈里有一颗 6 轴 IMU（加速度 + 陀螺仪）。这一步的输出是一串行为事件（几点几分、抓了多久、多大把握），交给第二步皮肤评估去算“这只狗今天抓得正不正常”。核心是把抓挠找准，同时把误报压低：误报会直接把皮肤评分抬高。

流程

① 采集项圈 IMU 20 Hz，6 轴；同时录视频当“答案”
② 标注平台视频 + 波形对齐标片段；模型先给疑似片段，人来确认
③ 训练8 秒窗口；按“天 × 项圈”分组 5 折，防止同一只狗同一天泄漏
④ 后处理动作门 + Viterbi 平滑，把逐窗结果连成事件
⑤ 端侧导出int8 1D-CNN，导出 C 数组进固件
⑥ 服务端XGB / CNN 推理服务，给平台打候选、给 App 复核
评估口径：片段级——人工标的一段抓挠，模型只要在里面报出来就算“命中”；模型报了但人工没有，就算“误报”，按每小时次数统计。这比逐窗准确率更接近用户真实感受。

算法模块和进展

抓挠识别可用，在打磨

91.8% 片段命中（6 轴 端侧 CNN）

查准约 94–95%，误报约 4–5 次/小时。

  • 3 轴版本（只用加速度）：87.3%
  • 服务端 XGB：92.0%，但误报约 8 次/小时
  • 加了公开狗数据集一起训，稳定了 1–2 个点

静止 / 活动 / 未佩戴已稳定

0.98 未佩戴 F1

“动作门”：先判断有没有在动，静止和没戴的窗口直接不送去分细类，既省电又少误报。佩戴时长也是皮肤评估里“每佩戴小时抓几次”的分母。

负例：吃、喝、嗅、舔、啃、蹭在补数据

≈51% 规则候选被人确认的比例

这些动作最容易被误认成抓挠。做法：用“负例挖掘模型”（训练记录 #43）在大量未标数据里找疑似片段，人一次只集中确认一类。

  • 饮水 48 / 进食 133 条候选已判，确认率都在 51–52%
  • IMU 相似度找喝水：模型概率前 10 命中 22.6%，比手工特征（17.2%）和随机（2.6%）好，但还不够当自动标签

甩头 / 抖身偏弱

0.16–0.24 F1（端侧）

服务端 XGB 到 0.33。动作只有 1–2 秒，在 8 秒窗口里被稀释。11-18 试了 FilterNet 逐点输出、大小窗口并行，都没变好；精准版把起止对齐率从 9.8% 提到 53.4%。真正缺的是数据（只有约 170 段）。

事件切分与起止可用

≈0.6 s 起止误差（精准版）

逐窗概率 → 动作门 → Viterbi（稳定版 v2）→ 精准版：平移掉 v2 起点偏早、终点偏晚的系统偏差，再按 3–9 Hz 抓挠节律能量对齐。

  • 抓挠终点误差 1.75 → 0.58 s，起止对齐 46.6% → 53.5%
  • 甩头起止对齐 9.8% → 53.4%

端侧部署（int8）能跑，要再瘦身

236 KB Flash；RAM ≈24 KB

int8 与浮点结果 99% 一致（量化损失 0.4–1.4 个点）。GR5515 能放下；GR5513 预算 128 KB：通道减半的小模型 6.4 万参数、抓挠命中 90.3%，正在导出上板。

数据与标注平台持续增长

45.9 h 自有标注数据池 · 1450 个任务

另有公开狗 IMU 数据 22.8 h（Vehkaoja 2022、Marcato 2023），已登记成平台数据集。平台支持“现在重点补哪一类”、疑似片段待判计数、按类筛选、清理候选。
