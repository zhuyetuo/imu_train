从项圈 IMU 里认出抓挠、舔、甩头、吃喝和休息

项圈里有一颗 6 轴 IMU（加速度 + 陀螺仪）。这一步的输出是一串行为事件（几点几分、抓了多久、多大把握），交给第二步皮肤评估去算“这只狗今天抓得正不正常”。核心是把抓挠找准，同时把误报压低：误报会直接把皮肤评分抬高。

流程

① 采集项圈 IMU 20 Hz，6 轴；同时录视频当“答案”
② 标注平台视频 + 波形对齐标片段；模型先给疑似片段，人来确认
③ 训练4 秒窗口、0.5 秒步长（端侧现有版本 8 秒）；按“天 × 项圈”分组 5 折，防止同一只狗同一天泄漏
④ 后处理动作门 + Viterbi 平滑，把逐窗结果连成事件
⑤ 端侧导出int8 1D-CNN，导出 C 数组进固件
⑥ 服务端XGB / CNN 推理服务，给平台打候选、给 App 复核

评估指标：三层口径

行为识别同时要分类（这几秒是不是抓挠）和切分（从几点抓到几点），所以分三层看：越往下越严，验收只认事件级。

  1. 窗口重叠 8 倍（4 s / 0.5 s），相邻窗口高度相关，窗口级天然偏乐观。
  2. 稀疏标注（每个文件只标约 0.8% 的时间）：误报 / 小时是下限；事件查准把所有预测放进分母，偏保守。
  3. 人标边界本身约 1 秒误差，IoU 0.5 对 2 秒的段很苛刻。
  4. 交叉验证和现场分布仍有差异（影棚争议），要按场地拆开、配合失败样本回放。

多尺寸（multi-scale）

做法：多核并行（k=3/5/7）、短窗 + 长窗双流、金字塔、便宜门控在前的级联。

我们：11-18 试过 FilterNet 逐点 + 大小窗口并行，没有变好；8 s 和 4 s 现在是两个独立模型。下一步值得试 4 s + 8 s 双流，先算端侧 RAM。

many-to-many（逐点输出）

输入一段序列、每个时间点都输出类别（1D U-Net / TCN / MS-TCN），边界由模型直接给。

没直接上：标注是段级、端侧要流式状态、算力更大。现在用“滑窗 + Viterbi + 后处理”近似；瓶颈确认在短段边界后再做。

学术界 / 产业界常见做法、步长机制、后处理常数
维度学术界产业界
窗口 / 步长HAR 多为 1–5 s 窗、50–75% 重叠（UCI HAR 2.56 s / 50%）；窗口覆盖 1–2 个动作周期睡眠 30 s 一个 epoch；手环 1–5 s、50% 重叠；窗口由 RAM / 功耗倒推
输出方式有逐点标签时用 many-to-many绝大多数 many-to-one + 后处理（中值滤波、最短时长、合并、滞回）
多尺度Inception 多核、空洞卷积、双流、级联资源允许才上；更多是“一个窗口 + 强后处理”
  • 步长：重叠率 = 1 − 步长 / 窗口。步长决定端侧功耗（0.5 s = 每秒算 2 次）和最短事件（2 个窗 ≈ 1 s）。
  • 训练窗：只在每段标注内部切，不跨类别、不跨掉包（>0.3 s 无数据）；短段以中心取窗、左右挪 2 档增强，验证不增强。
  • 后处理常数：进入 0.5 / 维持 0.25（滞回）、最短 2 个窗、段平均 ≥0.45、间隔 ≤4 s 合并。
  • 输入：CNN 吃重力对齐后的 6 轴；6 轴 → 3 轴约掉 2 个点。
一句话：现在是“4 s 窗 / 0.5 s 步 / 每窗一个标签 + 后处理”，瓶颈是 3 s 以内的短段。下一步先扫 2 s / 3 s 窗，再考虑多尺度或逐点输出，别再单纯加大窗口。

静止 / 活动 / 未佩戴已稳定

0.98 未佩戴 F1

“动作门”：先判断有没有在动，静止和没戴的窗口直接不送去分细类，既省电又少误报。佩戴时长也是皮肤评估里“每佩戴小时抓几次”的分母。

负例：吃、喝、嗅、舔、啃、蹭在补数据

≈51% 规则候选被人确认的比例

这些动作最容易被误认成抓挠。做法：用“负例挖掘模型”（训练记录 #43）在大量未标数据里找疑似片段，人一次只集中确认一类。

  • 饮水 48 / 进食 133 条候选已判，确认率都在 51–52%
  • IMU 相似度找喝水：模型概率前 10 命中 22.6%，比手工特征（17.2%）和随机（2.6%）好，但还不够当自动标签

甩头 / 抖身偏弱

0.16–0.24 F1（端侧）

服务端 XGB 到 0.33。动作只有 1–2 秒，在 8 秒窗口里被稀释。11-18 试了 FilterNet 逐点输出、大小窗口并行，都没变好；精准版把起止对齐率从 9.8% 提到 53.4%。真正缺的是数据（只有约 170 段）。

事件切分与起止可用

≈0.6 s 起止误差（精准版）

逐窗概率 → 动作门 → Viterbi（稳定版 v2）→ 精准版：平移掉 v2 起点偏早、终点偏晚的系统偏差，再按 3–9 Hz 抓挠节律能量对齐。

  • 抓挠终点误差 1.75 → 0.58 s，起止对齐 46.6% → 53.5%
  • 甩头起止对齐 9.8% → 53.4%

端侧部署（int8）能跑，要再瘦身

236 KB Flash；RAM ≈24 KB
