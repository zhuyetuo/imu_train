# 特征工程说明

`src/ml/features.py` 对每个时间窗口（默认2秒，16Hz采样即32个数据点）提取手工特征，供随机森林等传统机器学习模型使用。

## 输入通道

```
0:3  acc_x, acc_y, acc_z   ← 三轴加速度（重力对齐后）
3:6  gyr_x, gyr_y, gyr_z   ← 三轴角速度（重力对齐后）
6:8  pitch, roll           ← 姿态角（原始未对齐，见下方"姿态特征"说明）
```

共8个通道。前6个通道逐个独立提取特征，另有跨通道的全局特征（SMA、轴间相关系数）、合成模长特征（旋转不变）、Jerk特征（动作突然性）。姿态角两个通道只提取时域统计量，不提取频域特征（姿态是缓变量，不是振荡信号）。

**总特征维度**：
- 时域：11个特征 × 8通道 = 88
- 频域：8个特征（4个统计量 + 4个分频段能量）× 6通道（仅acc+gyro） = 48
- 全局：SMA×2（acc、gyro各一个） + 轴间相关系数×6（acc三对 + gyro三对） = 8
- 模长：acc模长 + gyro模长，各(11个时域+8个频域=19个) = 38
- Jerk：acc-jerk模长的11个时域特征 = 11
- **合计：193维**

---

## 时域特征（每通道11个）

| 特征 | 计算方式 | 物理意义 |
|---|---|---|
| **均值 (mean)** | 窗口内数值平均 | 该轴的整体倾向 |
| **标准差 (std)** | 窗口内数值波动程度 | **运动剧烈程度的核心指标**。抓挠时肢体快速抖动，std会明显高于睡觉和一般活动 |
| **最小值 / 最大值** | 窗口内极值 | 反映极端姿态/角速度 |
| **极差 (max-min)** | 最大值减最小值 | **动作幅度** |
| **均方根 (RMS)** | √(平均值²) | 能量强度的稳健度量 |
| **偏度 (skewness)** | 分布的不对称程度 | 间歇性动作（抓一下停一下）信号分布可能不对称 |
| **峰度 (kurtosis)** | 分布的尖锐程度 | **区分"间歇性剧烈动作"与"持续性动作"的关键特征**。抓挠是短促爆发式动作，峰度高 |
| **均值穿越率 (mcr)**（原"过零率"，已修正） | 信号穿越**窗口自身均值**的次数 | **反映动作的"抖动频率"，实测里是判别力最强的特征类型（EDA中Top10里6个是它）**。旧版是穿越绝对0，对有直流偏置的通道（如重力对齐后的acc_z恒受重力影响，几乎不可能变负）会失效；改成穿越自身均值后对所有通道都有意义 |
| **四分位距 IQR (Q3-Q1)** | 75分位数减25分位数 | 比标准差更抗突发尖峰噪声——比如项圈被意外碰撞产生的孤立尖峰，会明显拉高std但对IQR影响很小，是更稳健的波动量度 |
| **局部极值计数 (peak_count)**（新增） | 窗口内局部峰值的个数 | **均值穿越率的补充，直接量化"动了几次"**。mcr统计的是穿越均值的次数，peak_count统计的是波峰个数，波形不对称（比如抓挠这种发力快、回位慢的动作）时两者不完全等价，能提供互补信息。对于路线图里"重复性动作"（舔舐/抓挠/啃咬）尤其有意义——峰值个数接近"这2秒内动了几下"这个直觉量 |

---

## 频域特征（每通道8个，仅acc+gyro共6通道）

先用 Welch方法 计算功率谱密度（PSD），提取：

| 特征 | 计算方式 | 物理意义 |
|---|---|---|
| **频谱均值** | 各频率按功率加权平均 | 信号的"平均振动频率" |
| **频谱标准差** | 频率分布的离散程度 | 频率成分是否集中 |
| **主频** | PSD最大值对应的频率 | **最关键判别特征之一**。抓挠通常有稳定的重复节律（约3-8Hz），与走路/摇尾巴等其他周期性动作的频率不同 |
| **频谱熵** | PSD分布的信息熵 | 熵越低说明能量集中在少数频率上（有规律的重复动作）；熵越高说明能量分散（随机运动） |
| **分频段能量占比 ×4**（新增） | PSD在4个频段（各占Nyquist的 0-12.5% / 12.5-37.5% / 37.5-75% / 75-100%）内的能量占总能量的比例 | 主频只反映"能量最大的一个点"，分频段能量给出**完整的能量分布形状**，信息量比单一主频丰富得多。例如走路的步态能量可能集中在低频段，抓挠集中在中高频段，甩头/啃咬可能在更高频段有明显能量 |

---

## 全局特征（跨轴，新增）

这两类特征不再逐轴独立提取，而是利用三轴之间的关系，分别对加速度三轴 (acc_x,y,z) 和角速度三轴 (gyr_x,y,z) 各算一份：

| 特征 | 计算方式 | 物理意义 |
|---|---|---|
| **信号幅值面积 SMA** | `mean(\|x\|+\|y\|+\|z\|)` | 三轴合并后的整体运动能量，不区分方向。比单轴std/RMS更稳健地反映"总体活跃程度"，是运动强度分级的常用指标 |
| **轴间相关系数 ×3**（xy/yz/xz） | 皮尔逊相关系数 | **捕捉不同轴之间的协同运动模式，是区分相似重复性动作的关键**。例如：抓挠是后腿单一方向的往复运动，某两轴可能高度同步（相关系数高）；甩头/甩身体的多轴运动方向更随机（相关系数低）；舔舐是头部小幅度规律运动，可能只在一两个轴上有强相关。现有的逐轴统计量完全丢失了这层信息 |

---

## 合成模长特征（新增，旋转不变）

```
|acc| = sqrt(acc_x² + acc_y² + acc_z²)
|gyr| = sqrt(gyr_x² + gyr_y² + gyr_z²)
```

对 `|acc|` 和 `|gyr|` 各自提取完整的10个时域 + 8个频域特征（共18维 × 2 = 36维）。

**为什么需要**：项圈会在狗脖子上转动或滑动，这是犬类可穿戴研究里反复被提到的痛点。单轴特征（acc_x的std、主频等）会随项圈朝向漂移，同一个动作在不同佩戴角度下单轴数值可能完全不同。**模长是彻底旋转不变的**——不管项圈转到哪个角度，三轴合成后的模长数值不变。相比"重力对齐"这种依赖每窗口重新估计旋转矩阵的间接方法，模长是更直接、更稳健的抗漂移特征，两者互补：对齐后的单轴特征保留了方向信息（比如区分不同轴上的运动模式），模长提供不依赖对齐准确性的强度基线。

`|gyr|` 同理还能区分**平移类运动**（走/跑，角速度模长低）和**旋转类运动**（转圈、摇头、翻滚，角速度模长高），这对识别"原地转圈"这类特定动作模式有帮助。

---

## Jerk 特征（新增，动作突然性）

```
jerk = Δacc / Δt   （加速度对时间的导数，即"加加速度"）
jerk_mag = |jerk| = sqrt(jerk_x² + jerk_y² + jerk_z²)
```

对 `jerk_mag` 提取10个时域统计量（均值/标准差/极值/RMS/偏度/峰度/过零率/IQR）。

**为什么需要**：现有的峰度、极差等特征能反映"有没有突发的大动作"，但反映不出"变化发生得有多快"。平缓的走路，加速度本身变化就是渐进的，jerk很小；而**惊吓反应、甩头、抓挠动作回位**这类瞬时急停急起的动作，加速度的变化率会出现明显尖峰，即便峰值加速度本身不算特别大，jerk也会很突出。这是区分"平缓行走"和"警觉/受惊反应"的关键维度，也可能有助于捕捉抓挠动作里"抓一下快速收回"的瞬时特征。

只对加速度算 jerk（角加速度可类推但为控制维度膨胀暂不加）。

---

## 姿态特征（原始未对齐）

```python
pitch = atan2(-acc_x, sqrt(acc_y² + acc_z²))
roll  = atan2(acc_y, acc_z)
```

**⚠️ 关键实现细节：这两个通道必须用重力对齐*之前*的原始加速度计算。**

原因：`gravity_align`（见 `src/data/gravity_align.py`）会把每个窗口旋转，使该窗口的平均加速度方向对齐到 +Z 轴。这是为了让特征具有"围绕偏航轴的旋转不变性"（不管项圈戴的角度朝哪，抓挠动作的时域/频域特征都一致）。但代价是：**对齐之后，每个窗口的平均倾角必然趋近于0，狗的绝对姿态信息（趴/坐/站）会被完全抹掉**。

所以姿态角必须在对齐前，从原始加速度单独计算好，再作为两个额外通道拼接回对齐后的acc/gyro数据（`append_raw_tilt_batch`，代码里 `preprocess.py`、`infer_csv_scratch.py`、`infer.py`、`train.py`（合成数据分支）都在重力对齐前调用了这个函数）。

**物理意义**：这不是"动得多剧烈"，而是"身体处在什么姿态"。
- 区分趴/坐/站等静态姿态
- 摩擦（蹭痒）等行为可能伴随特定姿态（侧躺蹭地/蹭墙）
- 过度梳理可能伴随身体蜷曲姿态
- 结合"姿态 + 动态特征"能提升相似动作之间的区分度（例如"坐着舔爪子" vs "站着甩头"，姿态直接不同，即使动态特征相近）

---

## 为什么这套特征能区分"活动 / 睡觉 / 抓挠"

| 行为 | acc std/RMS | 过零率 | 主频 | 频谱熵 | SMA/模长 | 轴间相关 | Jerk |
|---|---|---|---|---|---|---|---|
| **睡觉** | 很低 | 很低 | 接近0Hz | 很低 | 很低 | 无意义（几乎无信号） | 很低 |
| **活动**（走动、玩耍） | 中到高，相对平稳 | 中等 | 较低且分散（步态约1-3Hz） | 中等 | 中到高 | 中等，随运动类型变化大 | 中等，渐进变化 |
| **抓挠** | 高且带突发峰值（峰度高） | 高（快速抖动） | 集中在特定较高频段（约3-8Hz） | 较低（规律性强） | 高 | 特定轴对可能同步性强（往复运动） | 高，回位动作产生尖峰 |

## 已知局限

1. **窗口固定2秒**：单次动作明显短于或长于2秒时，窗口内会混入其他行为的信号
2. **姿态角的时序信息未充分利用**：目前只对pitch/roll做时域统计（均值/标准差/峰度等），没有单独建模"姿态变化的时序模式"（比如从躺到坐的过渡）
3. **合成数据（`synthesize_scratch.py`）的原始增强逻辑不含姿态多样性**：数据增强目前主要在时域做变换，姿态角是从增强后的数据反算的，可能无法完全覆盖真实场景下的姿态分布
4. **Jerk只对加速度算，角加速度（gyro的Jerk）暂未加入**：如果后续发现"旋转类突发动作"（比如快速摇头）区分度不够，可以补上
5. **未做显式的低通/高通滤波分离**：目前用"每窗口重力对齐"隐式实现姿态与动态分量的分离（对齐后窗口均值被强制到固定方向，std/RMS天然反映去均值后的动态强度），没有采用经典的低通滤波提取重力分量、高通滤波提取动态分量的实现方式。两种方法效果接近，如果未来窗口变长（不再是2秒），建议改用显式滤波，因为窗口越长，"整窗均值≈重力方向"这个假设越容易被慢速姿态转换破坏

# 行为分类体系

## 当前：3分类（`configs/remap_custom_3class.yaml`）

```
活动   活跃状态（走动、玩耍等一般性运动）
睡觉   静息状态
抓挠   目标检测行为，用于健康监测预警
```

这是当前所有训练/推理脚本（`train_custom.sh`、`run_review_bins_all_days.sh`）默认使用的分类体系。

## 规划中：瘙痒行为细分类

犬瘙痒可表现为多种具体动作，目前全部归并为"抓挠"一类，未来计划拆分为：

```
抓挠 (scratching)     后腿/前爪抓挠身体
舔舐 (licking)        舌头舔舐身体某处
啃咬 (biting/chewing) 牙齿啃咬皮肤/毛发
摩擦 (rubbing)        身体蹭地面/家具/墙壁
过度梳理 (over-grooming) 持续性理毛，超出正常清洁频率
```

**这几类行为彼此高度相似**——单纯的运动幅度（std/RMS）区分不开它们，这也是本次新增"轴间相关系数"和"姿态特征"的直接动机：不同动作虽然运动强度接近，但涉及的身体部位、动作方向、伴随姿态不同，需要更细粒度的特征才能分开。

## 规划中：其他日常行为

```
吃饭 (eating)   进食
喝水 (drinking) 饮水
跳跃 (jumping)  跳上/跳下
甩动 (shaking)  甩头/甩身体（抖毛、驱赶昆虫等）
```

这些行为与瘙痒无关，但和"活动"这个大类里的具体子行为有关，细分后能让"活动"类别的召回率和精度都更准确，同时未来也可能作为独立的监测维度（比如吃饭/喝水频率异常可能是健康信号）。

## 对特征工程的影响

从3分类扩展到多分类（尤其是瘙痒行为细分类）时：
- **窗口长度可能需要按行为类型调整**：舔舐/过度梳理可能持续时间比抓挠长，固定2秒窗口可能不够
- **轴间相关系数、姿态特征、分频段能量会成为区分相似行为的主力特征**（单轴时域统计量对这些行为的区分力有限）
- **数据量要求会显著提高**：类别越多，每类需要的标注样本量越大，当前几十条狗、几千个窗口的规模对5+类别的细分类可能不够，需要持续通过 Label Studio 复查纠错循环积累数据
