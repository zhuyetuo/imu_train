# 行为识别（重点：抓挠）提升工作日志

> 由 Claude 端到端负责（2026-11 起）。目标：**端侧（GR5515，只开加速度）抓挠识别 90%+，误报不高于稳定版 v2**。
> 这份文件记录做了什么、怎么做的、结果如何、还剩什么，每完成一步更新一次。

## 约定

- **不改人工标注的原始数据**（平台数据库 / 原始导出不动）。自动改标的结果另存成新的训练数据集，
  每一处改动记录「改了什么、为什么」，随时可以对照、撤回。
- 评估一律按（天 × 项圈）分组交叉验证：同一只狗同一天不会同时出现在训练和验证里。
- 事件级评估：连续数据上推理 → 稳定版 v2 后处理（viterbi）→ 跟人标的抓挠片段配对；
  比较方法时在**相同误报水平**下比查全（抓挠概率乘一组系数扫一遍）。
- 训练 / 验证只用**数据池**（平台 scope=pool 导出），不用其它已有数据集（2026-11-16 用户要求）。

### 2026-11-14 ~ 15：摸底 + 修模型的问题
- job29（随机森林，pool_20261107）分组交叉验证窗口准确率约 0.80，抓挠 F1 约 0.67。

  → `still_motion_g`：这两类按 4 秒内 |a| 标准差重新分（aff43ec），主数据集窗口准确率 0.84 → 0.95。
- 平台界面加了这两个勾选（label_infra 8fcb4ca / 7fc56fa）。

### 2026-11-16：用户反馈「新模型误报多、稳定版 v2 漏报但很少误报」→ 三大类方法对比
- 修了 `merge_forest` 某一折缺细类时崩溃的 bug（c16f03b）。
- 新建数据集 **pool_20261116_all**（平台「导出数据集」，scope=pool，不加任何筛选 = 数据池全部）：
  1450 任务、5551 段、45.9 小时；抓挠 4651 段，活动 525、静止 101、未佩戴 20，舔 / 啃 / 饮水几乎没有。
- 规则 / RF / XGB / 1D-CNN × 6 轴 / 只加速度，分组 5 折（脚本 `~/claude_exp/compare3.py`、`eval_events.py`）：

| 方法 | 窗口：抓挠 F1（6 轴 → 只加速度） | 事件：误报 ≈3.4~4.5 次/小时时的抓挠检测率（6 轴 → 只加速度） |
|---|---|---|
| 稳定版 v2（6 轴，概率 ×2.5） | — | 46% |
| 规则 | 0.67 → 0.67 | 误报约 30 次/小时才到 88% |
| RF | 0.65 → 0.67 | 47% → 53%（误报 4.7） |
| XGB | 0.86 → 0.82 | 81% → 75% |
| **1D-CNN** | **0.89 → 0.87** | **76% → 73%** |

  （误报 = 人标成别的动作的 35.3 小时里报出的抓挠，pool 里这些时间多挨着抓挠，绝对值偏高，只适合横向比。）
- 结论：**端侧用「只开加速度 + int8 1D-CNN」**：关陀螺仪只掉约 3 个点，CNN 最小（约 30 KB）、不用算特征。
  CNN 的短板：静止 F1 只有 0.32——int8 之后静止 / 未佩戴只差一两个 LSB，看不见。

## 待办（按优先级）

1. [进行中] CNN 接进平台训练、推理、端侧导出（端侧 C 也要加动作门 tm_gate）。
2. **自动改标（不动原始标注，另存新数据集）**：
   - 用交叉验证（没见过这个文件的模型）的概率找「标签跟信号明显对不上」的片段（confident learning 思路），
     比如标抓挠但整段几乎不动、标活动但有持续 4~8Hz 节律；
   - 抓挠片段边界按 4~8Hz 节律能量收紧 / 放宽（人标的起止常差 1~2 秒）；
   - 每处改动写进 `relabel_log.csv`（文件、原起止、原标签、新起止、新标签、依据），抽样人工复核一小部分确认改对了。
3. **用 NAS 上没标注的数据**：
   - 自监督预训练（对比学习 / 掩码重建）一个大一点的编码器，再在数据池上微调；
   - 伪标签：高置信度的抓挠 / 非抓挠片段加进训练（尤其补舔、啃、饮水这类负样本——误报主要来源）；
   - 最后蒸馏回板上那个小 CNN（资源不变）。
4. CNN 结构：深度可分离卷积、膨胀卷积 / TCN（看 8~16 秒上下文区分持续抓挠和一下一下的舔啃）、多尺度卷积核。
5. MiniRocket 做个便宜的对照组（随机卷积核 + 线性分类，需要移植 C）。
6. 级联省电：极便宜的「有没有在动 / 有没有节律」门先过一遍，可能是抓挠才跑 CNN。
7. 聚类：用在查标注（标抓挠却落在活动簇）、主动学习挑数据、发现子类，不直接当分类器。
8. 板上固件：tm_post 喂时间戳要加 (窗口-步长)/2 偏移；GBDT / CNN 的 board/ 工程接入和真机实测。

## 2026-11-17 量化、负例挖掘、平台登记规范

### 端侧 int8 量化：损失其实很小，之前的「89% 一致」是评估算错了
- 导出脚本拿「int8 + 动作门」去比「float 不过门」：未佩戴 / 静止在板上本来不归 CNN 判，两边必然对不上。
  同一批留出窗口两边都过门之后：3 轴一致 99.0%（CNN 实际判的窗口 98.2%），6 轴 99.2%（98.6%）。
  抓挠 F1 float → int8：3 轴 0.929 → 0.925，6 轴 0.953 → 0.939。
- 挑量程那几档在 50%~89% 之间乱跳也是同一个原因。已修（algo_tinyml 80dc808）：挑量程、算一致率时两边都过同一个门。
- 试过的两条路：
  - 放大校准集（每类 50 → 200 窗）：没用，最终一致率不变，没提交。
  - 量化感知训练（QAT，train_v2 model_params.qat_epochs，默认关，imu_train 1fbf188）：3 轴在 99.0 档一致率 86% → 92.6%，

### 待做：用户 11-18 提的 7 个方向（一个个来）

1. **陀螺仪按需开**：一天开陀螺仪不超过 2 小时。3 轴 vs 6 轴同误报差 2~3 个点。思路：3 轴模型常开当触发器，疑似抓挠 / 剧烈活动时开陀螺仪 30~60 s 给 6 轴模型确认。

### 3. 原始 IMU 压缩上传（`experiments/claude_2026_11/compress_eval.py`，60 个文件 57.5 h 真实数据，按设备原始量化）

| 每天（20 Hz） | 3 轴 | 6 轴 |
|---|---|---|
| 原始 int16 | 10.4 MB | 20.7 MB |
| 差分 + 变长字节 | 6.2 MB | 12.4 MB |
| **差分 + 分块 Rice（无损，单片机几十行 C）** | **4.3 MB（2.4×）** | **8.2 MB（2.5×）** |

最简单的差分 + Rice 比通用压缩还小（跟 FLAC 一个思路）。这批是活动多的录制，真实一天大半在睡，压缩比只会更好。

平台 AI 结果（196 个文件 182 h）：未佩戴 40.5%、睡觉 35.3%、活动 20.3%、掉数据 4%。戴着的时间里约六成在睡 / 静止 →

### 5. CMSIS-NN vs 现在的推理（docs/frameworks.md 9 月已调研）

结论不变：**不换推理框架，只换 CMSIS-NN 算子**（已做，-DTM_CMSIS_NN=1，包里两个版本都有）。TFLite Micro 一类光算子就 50~200 KB，
比模型本身还大；我们的模型结构固定，背解释器换不回东西。train40 实测：每窗 332 万次 int8 乘加；宿主机模拟普通版 1.87 ms、CMSIS-NN 0.65 ms（快 2.9×，
Arm 给的上板数据约 4.6×）；代价 Flash +7 KB、RAM +5 KB（im2col），输出跟普通版一致（个别值差 1 LSB，类别不变）。待上板实测。

  前提：卷积不补零（valid），步长是 8 个采样点的整数倍（池化对齐；20 Hz 下 0.4 / 0.8 s），中间层缓存约 12 KB RAM。正在测不补零结构的精度。
