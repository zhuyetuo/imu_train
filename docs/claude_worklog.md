# 行为识别（重点：抓挠）提升工作日志

> 由 Claude 端到端负责（2026-11 起）。目标：**端侧（GR5515，只开加速度）抓挠识别 90%+，误报不高于稳定版 v2**。
> 这份文件记录做了什么、怎么做的、结果如何、还剩什么，每完成一步更新一次。

## 约定

- **不改人工标注的原始数据**（平台数据库 / 原始导出不动）。自动改标的结果另存成新的训练数据集，
  每一处改动记录「改了什么、为什么」，随时可以对照、撤回。
- 评估一律按（天 × 项圈）分组交叉验证：同一只狗同一天不会同时出现在训练和验证里。
- 事件级评估：连续数据上推理 → 稳定版 v2 后处理（viterbi）→ 跟人标的抓挠片段配对；
  比较方法时在**相同误报水平**下比查全（抓挠概率乘一组系数扫一遍）。
- 训练 / 验证只用**数据池**（平台 scope=pool 导出），不用其它已有数据集（2026-11-16 用户要求）。

### 2026-11-14 ~ 15：摸底 + 修模型的问题
- job29（随机森林，pool_20261107）分组交叉验证窗口准确率约 0.80，抓挠 F1 约 0.67。

  → `still_motion_g`：这两类按 4 秒内 |a| 标准差重新分（aff43ec），主数据集窗口准确率 0.84 → 0.95。
- 平台界面加了这两个勾选（label_infra 8fcb4ca / 7fc56fa）。

### 2026-11-16：用户反馈「新模型误报多、稳定版 v2 漏报但很少误报」→ 三大类方法对比
- 修了 `merge_forest` 某一折缺细类时崩溃的 bug（c16f03b）。
- 新建数据集 **pool_20261116_all**（平台「导出数据集」，scope=pool，不加任何筛选 = 数据池全部）：
  1450 任务、5551 段、45.9 小时；抓挠 4651 段，活动 525、静止 101、未佩戴 20，舔 / 啃 / 饮水几乎没有。
- 规则 / RF / XGB / 1D-CNN × 6 轴 / 只加速度，分组 5 折（脚本 `~/claude_exp/compare3.py`、`eval_events.py`）：

| 方法 | 窗口：抓挠 F1（6 轴 → 只加速度） | 事件：误报 ≈3.4~4.5 次/小时时的抓挠检测率（6 轴 → 只加速度） |
|---|---|---|
| 稳定版 v2（6 轴，概率 ×2.5） | — | 46% |
| 规则 | 0.67 → 0.67 | 误报约 30 次/小时才到 88% |
| RF | 0.65 → 0.67 | 47% → 53%（误报 4.7） |
| XGB | 0.86 → 0.82 | 81% → 75% |
| **1D-CNN** | **0.89 → 0.87** | **76% → 73%** |

  （误报 = 人标成别的动作的 35.3 小时里报出的抓挠，pool 里这些时间多挨着抓挠，绝对值偏高，只适合横向比。）
- 结论：**端侧用「只开加速度 + int8 1D-CNN」**：关陀螺仪只掉约 3 个点，CNN 最小（约 30 KB）、不用算特征。
  CNN 的短板：静止 F1 只有 0.32——int8 之后静止 / 未佩戴只差一两个 LSB，看不见。

## 待办（按优先级）

1. [进行中] CNN 接进平台训练、推理、端侧导出（端侧 C 也要加动作门 tm_gate）。
2. **自动改标（不动原始标注，另存新数据集）**：
   - 用交叉验证（没见过这个文件的模型）的概率找「标签跟信号明显对不上」的片段（confident learning 思路），
     比如标抓挠但整段几乎不动、标活动但有持续 4~8Hz 节律；
   - 抓挠片段边界按 4~8Hz 节律能量收紧 / 放宽（人标的起止常差 1~2 秒）；
   - 每处改动写进 `relabel_log.csv`（文件、原起止、原标签、新起止、新标签、依据），抽样人工复核一小部分确认改对了。
3. **用 NAS 上没标注的数据**：
   - 自监督预训练（对比学习 / 掩码重建）一个大一点的编码器，再在数据池上微调；
   - 伪标签：高置信度的抓挠 / 非抓挠片段加进训练（尤其补舔、啃、饮水这类负样本——误报主要来源）；
   - 最后蒸馏回板上那个小 CNN（资源不变）。
4. CNN 结构：深度可分离卷积、膨胀卷积 / TCN（看 8~16 秒上下文区分持续抓挠和一下一下的舔啃）、多尺度卷积核。
5. MiniRocket 做个便宜的对照组（随机卷积核 + 线性分类，需要移植 C）。
6. 级联省电：极便宜的「有没有在动 / 有没有节律」门先过一遍，可能是抓挠才跑 CNN。
7. 聚类：用在查标注（标抓挠却落在活动簇）、主动学习挑数据、发现子类，不直接当分类器。
8. 板上固件：tm_post 喂时间戳要加 (窗口-步长)/2 偏移；GBDT / CNN 的 board/ 工程接入和真机实测。

## 2026-11-17 量化、负例挖掘、平台登记规范

### 端侧 int8 量化：损失其实很小，之前的「89% 一致」是评估算错了
- 导出脚本拿「int8 + 动作门」去比「float 不过门」：未佩戴 / 静止在板上本来不归 CNN 判，两边必然对不上。
  同一批留出窗口两边都过门之后：3 轴一致 99.0%（CNN 实际判的窗口 98.2%），6 轴 99.2%（98.6%）。
  抓挠 F1 float → int8：3 轴 0.929 → 0.925，6 轴 0.953 → 0.939。
- 挑量程那几档在 50%~89% 之间乱跳也是同一个原因。已修（algo_tinyml 80dc808）：挑量程、算一致率时两边都过同一个门。
- 试过的两条路：
  - 放大校准集（每类 50 → 200 窗）：没用，最终一致率不变，没提交。
  - 量化感知训练（QAT，train_v2 model_params.qat_epochs，默认关，imu_train 1fbf188）：3 轴在 99.0 档一致率 86% → 92.6%，

### 5. CMSIS-NN vs 现在的推理（docs/frameworks.md 9 月已调研）

## 2026-11-23：窗口 8s→4s/0.5s、抓挠指标按场地拆开、多尺寸不再重试

**多尺寸（多尺度 / 多窗口）不再重试**——11-18 已经做过对照（`experiments/claude_2026_11/ms_summary_20261118.md`、`docs/history.html`）：
- 双窗口（8s + 2s 并行）抓挠命中 91.7% vs 基线 91.8%，甩头 64.9% vs 69.5%，误报 6.07 vs 5.73 次/h；
- FilterNet 多尺度卷积 + 双向 LSTM 逐点输出：抓挠 81.8%、甩头 17.2%、98 万参数；
- 16s TCN：命中 93.5% 最高，但误报 7.43 次/h、起止 IoU 仅 15.9%。

结论：多尺寸在命中上没赢，甩头和起止反而更差；端侧 128KB flash + 固定窗口流式推理，多一份窗口就是算力和内存翻倍。**先解决单窗口长度，不再花时间重试多尺寸。**

**窗口 8s → 4s / 0.5s（job58）**
- 8s 窗口的误报一段至少 8 秒，一两秒的短抓挠容易被前后动作冲淡；4s 窗把最短误报段减半，0.5s 步长让起止更准。
- 平台训练版本行新增 `窗 Xs / 步 Xs` 标签（≥6s 标红，悬停说明窗口长度对误报段长的影响）。
- 结果（job58，726 秒）：片段级抓挠 查全 0.902 / 查准 0.979 / F1 0.939；按场地 F1 佛山博朗旺 0.937、公司影棚 0.961、深圳雷诺 0.936。总分没明显涨；**影棚交叉验证不差（0.961），和现场「一段都判不出」矛盾**——下一步先核对现场启用的模型版本、推理窗口/步长/预处理，再导出失败样本回放。
- 核对时发现：label_service 当前默认加载的仍是 8 月老 RF（1s 窗 / 0.5s 步、5 类），不是 job57/58；平台「启用模型」只改运行时，服务重启会回到 `LABEL_MODEL` 配置。现场如果走平台预标注，测的可能根本不是今天的 CNN。

**抓挠 P/R/F1 按场地分开报（train_v2 `per_site`）**
- 合在一起的总分会被样本多的场地盖住，看不出「佛山很准、影棚几乎判不出来」。

## 2026-11-23（续）：事件查全 0.65 → 0.78~0.82 的分解与诊断

**目标**：事件级抓挠查全（同类 + IoU≥0.5 + 一对一贪心，后处理之后，五折交叉验证按天×项圈分组）从 0.654 提到 **0.78~0.82**；
查准不能掉太多（目前 precision_iou50 = 0.733）。

**现状（#58，4s 窗 / 0.5s 步、6 轴 CNN、池+老抓挠+公开集）**

| 指标 | 值 |
|---|---|
| 整段至少盖到（any-overlap 命中率） | 0.8915 |
| 盖到的段里 IoU≥0.5 的比例 | 0.733 |
| 事件查全（两者相乘） | 0.6537 |
| 查准 / F1（IoU≥0.5） | 0.470 / 0.544（job60 同配置实测；#58 当时还没算查准） |

| 每场地宽松 F1 | 佛山 0.937 / 影棚 0.961 / 深圳 0.936 |

查全的两个乘数含义不同：
- **0.8915**：还有 10.85% 的真值段模型/后处理整段没报 → 模型问题（短段、弱动作）或后处理吞段（最小窗数、平均概率门槛、viterbi 平滑、合并间隔）；
- **0.733**：报到了但边界或时长差太多 → 后处理 / 窗口宽度问题（4s 窗最短预测段 4s，1~2s 的抓挠 IoU 天然到不了 0.5）。

**诊断（本次加进 train_v2）**：`segment_metrics()` 新增
- `by_len`：真值段按持续时间分桶 `<3s / 3–6s / 6–10s / ≥10s`，每桶给 `n_gt / hit / iou50 / hit_rate / iou50_rate / iou50_given_hit`；
  `hit_rate` 低 = 整段没报（模型问题），`iou50_given_hit` 低 = 盖到了但边界差（后处理问题）；
- `frag`：有重叠的真值段被切成几个预测段（中位数）、合起来盖住真值的比例（中位数），看碎片化。
写入 `postprocess_segments[类].by_len / .frag`，同时每类在训练日志里打印一张小表（不用去翻 JSON）。

`synthetic` 自测（4 段：2s/5s/7s/30s，其中 5s 段被切成两块、30s 段漏报）输出符合预期：
`lt3` 1/1/1、`3to6` hit 1 iou50 0、`6to10` 1/1/1、`ge10` 0/1，`frag` = 1 个预测段、覆盖 98.6%。

**拿到 by_len 后怎么定方向（决策树）**
1. 漏检集中在 `<3s` → 扫 2s / 3s 窗口（步长 0.5s），或短窗与 4s 双窗后处理合并；端侧只保留一个窗口的话，看短窗对长段的损失。
2. 漏检集中在 `≥10s`，或 `iou50_given_hit` 明显低于 `hit_rate`（尤其 3–6s 桶）→ 改后处理：最小预测段长、事件合并间隔、
   边界按信号（4–8Hz 包络）收紧/放宽、`STABLE_EVENT_MIN_MEAN` / `EVENT_SINGLE_CONF` 扫描。
3. `frag.preds_per_hit_median > 1.5` → 同一动作被切碎，优先加合并间隔（`STABLE_EVENT_GAP_S`），比换模型便宜。
4. 均匀地漏（各桶 hit_rate 都低）→ 模型本身：补标 / 类权重 / 校准系数（`class_scale` 抓挠 ×α）扫一遍。

## 2026-11-24 凌晨：抓挠事件级查准（别把不是抓挠的报成抓挠）

**目标（用户 11-23 晚提）**：提高事件级抓挠查准；起止差一些、片段长一些短一些都可以接受。

**口径**（`experiments/claude_2026_11/evt/evt_eval.py`，读 `TRAIN_V2_DUMP_SEG` 导出的交叉验证连续推理）：
- 预报的抓挠事件跟人标抓挠重叠 ≥0.5 s 就算对（不要求 IoU≥0.5）
- 确定误报 = 不对且落在人标的其他动作上；未标时间 = 不碰任何人标片段，单独数
- 确定查准 = 对 / (对 + 确定误报)（上限）；全部查准 = 对 / 全部预报（把未标时间都算错，下限）

**发现**：job60 配置（4 s / 0.5 s 6 轴 CNN）7075 个预报：对 4211、确定误报 422（活动 195、啃 91、进食 46、舔 38、饮水 24）、**未标时间 2442（35%）**。
未标时间里的预报跟确定误报的特征几乎一样（时长中位 4.0 s、段均概率 0.64、陀螺仪 std 39–45），跟真抓挠（8.8 s、0.82、58）差很远，离人标抓挠 ≤10 s 的只有 7.6%——**多数是真误报，不是漏标**。
根因：训练只用人标片段，模型没见过日常背景。

**做了什么**：
1. train_v2 加 `TRAIN_V2_DUMP_SEG`（e28b534）：交叉验证连续推理 + 每窗物理特征导出，后处理离线扫一轮 4 秒
