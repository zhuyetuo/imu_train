狗项圈行为识别 项目总览 业界进展与可选模型 代码仓库
项目效果总览 · 更新于 2026-11-17

用项圈上的 IMU，认出狗在抓挠、舔、甩头、吃喝和休息

项圈里有一颗 6 轴 IMU（加速度 + 陀螺仪）。我们把它的数据采下来、在标注平台上配视频打标签，训练出两套模型：一套量化成 int8 放进项圈芯片里实时跑，一套放在服务端做更准的复核。核心目标是把抓挠（皮肤问题的信号）找准，同时把误报压低，其他行为逐步补上。

这个项目在做什么

① 采集项圈 IMU 20 Hz，6 轴；同时录视频当“答案”
② 标注平台视频 + 波形对齐标片段；模型先给疑似片段，人来确认
③ 训练8 秒窗口；按“天 × 项圈”分组 5 折，防止同一只狗同一天泄漏
④ 后处理动作门 + Viterbi 平滑，把逐窗结果连成事件
⑤ 端侧导出int8 1D-CNN，导出 C 数组进固件
⑥ 服务端XGB / CNN 推理服务，给平台打候选、给 App 复核
评估口径：片段级——人工标的一段抓挠，模型只要在里面报出来就算“命中”；模型报了但人工没有，就算“误报”，按每小时次数统计。这比逐窗准确率更接近用户真实感受。

用到哪些算法模块、各自进展

抓挠识别可用，在打磨

91.8% 片段命中（6 轴 端侧 CNN）

查准约 94–95%，误报约 4–5 次/小时。

  • 3 轴版本（只用加速度）：87.3%
  • 服务端 XGB：92.0%，但误报约 8 次/小时
  • 加了公开狗数据集一起训，稳定了 1–2 个点

静止 / 活动 / 未佩戴已稳定

0.98 未佩戴 F1

“动作门”：先判断有没有在动，静止和没戴的窗口直接不送去分细类，既省电又少误报。

负例：吃、喝、嗅、舔、啃、蹭在补数据

≈51% 规则候选被人确认的比例

这些动作最容易被误认成抓挠。做法：用“负例挖掘模型”（训练记录 #43）在大量未标数据里找疑似片段，人一次只集中确认一类。

  • 饮水 48 / 进食 133 条候选已判，确认率都在 51–52%
  • IMU 相似度找喝水：模型概率前 10 命中 22.6%，比手工特征（17.2%）和随机（2.6%）好，但还不够当自动标签

甩头 / 抖身偏弱

0.16–0.24 F1（端侧）

服务端 XGB 到 0.33。动作只有 1–2 秒，在 8 秒窗口里被稀释；下一步试短窗口 / 逐帧切分。

事件切分与平滑可用

≈0.8 s 事件起点误差

逐窗概率 → 动作门 → Viterbi（稳定版 v2），输出“几点几分抓了多久”。

端侧部署（int8）能跑，要再瘦身

236 KB Flash；RAM ≈24 KB

int8 与浮点结果 99% 一致（量化损失 0.4–1.4 个点）。GR5515 能放下；GR5513 给模型的预算只有 128 KB，还要再压一半。

接下来

  1. 用已确认的负例重训挖掘模型和主模型
    目标：抓挠误报从 4–5 次/小时降到 2–3 次/小时，命中不掉。
  2. 甩头 / 抖身换短窗口或逐帧切分
    2 秒窗口或 MS-TCN 式的逐帧模型，专门对付 1–2 秒的短动作。
  3. 自监督预训练
    大量未标数据先做预训练，再用少量标签微调；业界在“标签少”的情况下普遍有提升。
  4. GR5513 小模型
    剪枝 / 蒸馏 / 更窄的网络，把 236 KB 压到 128 KB 以内。
  5. 用画面找喝水
    视频向量先找出候选，再回到 IMU 上确认。
