IMU 行为识别：别人用什么模型，哪些值得我们试

这一页回答一个问题：针对“项圈 IMU + 少量标签 + 小芯片”这个场景，有哪些比我们现在更好的模型可以用？先给结论，再给依据（时间线、模型演进、和别家对比）。

技术路线怎么演进的

阈值 / 规则计步、跌倒；简单但难扩展
手工特征 + RF/XGB统计、频域特征；我们服务端的 XGB 就在这层
CNN / LSTM端到端；我们端侧的 1D-CNN 在这层
TCN / Transformer更长上下文、逐帧切分
自监督 / 基础模型先吃大量未标数据，再少量标签微调
TinyML / 传感器内置反方向：把模型缩到 µA 级功耗
两条线同时在走：服务端越来越“大而通用”，端侧越来越“小而省电”。我们的位置是：端侧用小 CNN，服务端可以借大模型的力（预训练、蒸馏、找候选）。

为什么差几个点，怎么补

现象原因对应办法
抓挠误报 4–5 次/小时吃、喝、舔、啃的动作和抓挠很像，负例太少负例挖掘 + 一次一类确认（在做）；再重训
甩头 / 抖身 F1 只有 0.2 左右动作 1–2 秒，8 秒窗口里信号被稀释短窗口或逐帧切分（MS-TCN 一类）
换狗、换项圈掉点标签只覆盖少数狗加公开数据（已加 22.8 h）；方向无关输入 + 旋转增强（已用）
3 轴比 6 轴低约 4.5 个点少了陀螺仪的转动信息省电型号用 3 轴，精度型号用 6 轴；蒸馏可缩小差距
GR5513 放不下236 KB > 128 KB蒸馏到窄网络、剪枝、共享卷积核

方向我们别家公开最好能不能直接比

第二步：皮肤评估业界怎么做

做法谁在用怎么做对我们
项圈抓挠趋势 + 提醒Whistle、Vetrax 厂商统计每天抓挠 / 舔的时长和次数，比群体参考值或自己过去高就提醒和我们的 C 值思路一致；Whistle 的公开参考值我们用来做冷启动兜底
兽医瘙痒评分兽医临床（PVAS 瘙痒视觉评分）主人按 0–10 的描述给“痒的程度”打分可以加进问卷，当模型 B 的辅助标签
皮损评分兽医临床（CADESI-04，特应性皮炎）按身体部位给红斑、抓痕、秃毛打分模型 C 照片检测的类别可以参考它的部位和病变划分
照片 AI 看皮肤部分宠物 App拍照识别皮损类型模型 C 方向；单靠照片不知道“痒不痒”，和 IMU 互补
业界产品基本只做到“行为趋势 + 提醒”，把行为、问卷、照片合起来给分级的公开做法很少，这是我们第二步的差异点，也意味着没有现成的基准可比，只能靠兽医评级来验证。
