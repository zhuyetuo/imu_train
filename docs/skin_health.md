# 皮肤健康评估（基于抓挠行为）方案

## 0. 文档定位

产品侧已经出了正式的算法定义文档 **《Wardyn智能颈圈犬类行为识别算法定义文档 V0.4》**（2026-08-04，Owner：产品×算法联合维护），里面 `CARE_SCRATCH`（抓挠）标签的事件定义、Scratch Burden Score 评分结构、字段schema、验收门槛都已经定稿评审。**这份文档是当前的权威目标定义，本文件不再重复设计一套平行的评分方案，而是：**

1. 直接采用 PM 文档定义的评分结构（§2）、字段命名（§3）、验收标准（§5）
2. 补齐 PM 文档里留白/删除的部分——尤其是"个人基线"具体怎么算，这块 V0.4 版把定义删掉了，但下游字段还在用，需要算法侧给出可实现的具体方案（§2.3）
3. 明确列出文档里所有**经验值/待验证参数**，以及用现有工具（`event_eval.py`、`run_review_bins_all_days.sh`）怎么去验证（§4）——**这是当前算法工程侧最主要的工作，产品定义的具体取值仅供参考，最终以真实数据测试结果为准**
4. 保留此前收集的外部文献（Whistle FIT / Vetrax）作为参数校准的旁证，但不再作为设计主依据（§6）

## 1. 背景

现有 pipeline（`infer_csv_scratch.py`）已经能从 IMU 数据里识别出"抓挠"这一行为片段（起止时间、置信度）。这份文档要解决的问题是：把离散的抓挠事件流，转成 PM 文档定义的 Scratch Burden Score 和 C0/C1/C2 三档护理建议，并且验证/校准里面所有的经验参数。

工作分两块，互相独立：

- **A. 趋势报告**：把抓挠事件按 PM 文档字段规范聚合成日/周数据，供内部分析和后续产品展示用
- **B. Scratch Burden Score + 基线**：按 PM 定义实现评分逻辑，重点是补全"个人基线"的具体算法，并对所有经验参数做数据验证

## 2. Scratch Burden Score（按 PM 文档 V0.4 定义）

### 2.1 评分结构

PM 文档明确**不建议直接向用户展示 0–100 分**，只在算法内部计算，对外只展示 C0/C1/C2 三档：

```
Scratch Burden = 变化幅度(0-30) + 聚集程度(0-20) + 持续程度(0-20) + 正常行为影响/中断(0-30)
```

四个维度**全部是相对信号**（相对基线、相对当日模式、相对日间连续性、相对正常作息），**没有独立的绝对频率/时长阈值分项**——这一点比此前讨论过的"Whistle式分级+ChatGPT草案"更合理：那两版都是"60%权重挂绝对阈值+10%权重挂基线偏离"的结构，导致本身抓挠基线很低的狗，哪怕相对变化很大也很难触发高分（详见本文档旧版讨论，已被此结构取代）。PM 这版把绝对量纲完全排除在计分公式外，只用来做"聚集/中断"里的辅助判定条件（比如"1小时≥5次"），从根上避免了那个问题。

**红旗信号（Red-flag override）**：不参与加权平均，而是"命中即强制升级"规则，避免严重症状被其他低分维度稀释：

| 触发条件 | 效果 |
|---|---|
| 相对基线 > 3倍 | 变化幅度直接30分 |
| 当日聚集时段 ≥ 3个 | 聚集程度直接20分 |
| 连续偏离基线 ≥ 3天 | 持续程度直接20分 |
| 连续/高度聚集抓挠达到1分钟 | 直接触发红旗，"长时间抓挠事件" |
| 满足多种正常行为反复中断（≥2次）或持续抓挠≥60秒 | 正常行为影响直接30分 |

四个分项各自的红旗都命中30/20/20/30满分时，总分会自然落在 C2 区间；单一维度触发红旗不代表总分一定进 C2，需要看加总后落在哪个区间。

### 2.2 分数等级

```
C0 On Track：           0 ≤ C < 30
C1 Watch Closely：     30 ≤ C < 50
C2 Vet Check Recommended：50 ≤ C ≤ 100
```

对外文案只用 "detected / pattern / change / may be worth checking / consider contacting a veterinarian" 这类措辞，禁止 "diagnosed / confirms / has an infection / is in pain"。

### 2.3 个人基线——PM 文档留白，算法侧需要给出具体方案

V0.4 更新记录里写着"删除个人基线定义"，但 `Baseline_scratch_event_count`、`Baseline_scratch_total_duration_sec`、`baseline_delta_pct` 这些字段仍然是核心输出的一部分——**基线怎么算，目前是产品没有定、需要算法侧落地的部分**。

沿用此前的设计（基线窗口跳过最近7天，避免持续性异常被自我吸收进基线）：

```
X_base = median(X_{d-21}, ..., X_{d-8})   # 排除最近7天，取此前14天中位数
X_7d = 加权均值(X_d, X_{d-1}, X_{d-2}, ...) # 越近权重越高
```

`X_d` 可以是事件数、总时长，或两者的组合，取决于 §2.1"变化幅度"部分要求的"双值取大"（事件数和时长两个维度分别算倍数，取较高分）。

**双门槛判断**（PM文档表一）：同时满足"相对倍数"和"最小绝对增量"才计分。PM原文倍数计算时分母最低按3处理，我们的实现改成了按1处理（`BASELINE_DENOM_FLOOR=1`）——原因和验证过程见 §4.1，简单说就是"按3处理"会让基线≈0的狗即使稳定维持在新的、更高的抓挠水平上，也永远算不出变化幅度分：

| 基线变化 | 次数最小绝对增加 | 时长最小绝对增加 | 相对倍数 | 偏离分 |
|---|---|---|---|---|
| 无明显变化 | <3次/24h | <1分钟/24h | 不判断倍数 | 0 |
| 轻微变化 | ≥3次/24h | ≥3分钟/24h | 1.3~1.5倍 | 5 |
| 明显变化 | ≥5次/24h | ≥5分钟/24h | 1.5~2倍 | 10 |
| 显著变化 | ≥10次/24h | ≥10分钟/24h | 2~3倍 | 20 |
| 显著变化 | ≥20次/24h | ≥15分钟/24h | >3倍 | 30 |

### 2.3.1 基线未建立期间（<21天历史）怎么办——不是完全空白

刚绑定设备、基线数据不足（<21天历史，或基线窗口内有效天数<7天）时，**不用不完整的几天数据强行凑一个基线**——样本太少容易被头几天的偶然波动带偏，算出来的基线本身不可靠。

但也不能整个"变化幅度"分项完全空着——一只设备刚绑定就是重度抓挠的狗，不该等21天基线建立后才被发现。做法是**引导期内用绝对阈值兜底**，直接用 §6 引用的 Whistle FIT 已验证分级：

```
日总抓挠时长 ≥300秒/天 → 兜底分30分（对应 Whistle "Severe" 档），并标红旗 bootstrap_absolute_severe
日总抓挠时长 120~299秒/天 → 兜底分10分（对应 "Elevated" 档）
日总抓挠时长 <120秒/天 → 0分
```

"聚集程度"（1小时≥5次）和"长时间抓挠红旗"（单次≥60秒）本身不依赖基线，引导期内照常生效；"持续程度"这一项概念上依赖"连续偏离基线"，引导期内没有意义，暂不计分。基线一旦正式建立（≥21天历史+基线窗口内≥7天有效数据），立刻切回 §2.3 的相对基线评分，绝对阈值兜底规则退场。

这样设计下，引导期内的"温和但持续偏高"模式确实要等基线建立才能被发现（这类信号本身紧迫性也低，可以接受），但"当下就很严重"的情况（长时间抓挠、当日总时长破300秒、高度聚集）从第1天就能被兜底规则或不依赖基线的分项抓到，不会有21天的保护空窗期。

### 2.4 聚集程度、持续程度、正常行为中断

三块直接按 PM 文档定义实现，不重复展开公式，关键取值汇总见 §4（作为待验证参数清单的一部分）：

- **聚集程度**：1小时内（有效佩戴）抓挠事件≥5次记为1个聚集时段，当天聚集时段数决定得分
- **持续程度**：要求"当日变化幅度≥10分"才计入连续天数；某天数据不足12小时暂停计数（不重置不增加）；连续两个数据不足日则终止本次持续周期；最长回溯7天
- **正常行为中断**：核心是"抓挠相关睡眠中断"的判定——睡眠≥5分钟→抓挠事件≥3秒（或60秒内累计≥6秒）→中止后清醒≥3分钟才算一次中断；未重新稳定入睡（≥5分钟）的多次抓挠合并为同一次中断；相邻中断事件间隔≤5分钟也合并

## 3. 事件与字段定义（对齐 PM 文档 schema）

### 3.1 抓挠事件定义

| 概念 | 定义 |
|---|---|
| 抓挠动作（stroke） | 后肢完成一次"抓触—回摆"的周期，不单独展示 |
| 抓挠事件（event） | 开始：连续≥2个周期性抓挠动作，或信号持续≥1秒，且置信度达到起始阈值、设备有效佩戴；持续：间隔≤3秒的短暂停顿仍算同一事件；结束：连续>3秒未检测到抓挠，或转换为其他行为，或设备脱落/松动 |
| 有效佩戴（valid wear） | 设备正确佩戴、信号质量达标的时长 |

> **"3秒"是产品建议的算法参数，不是临床标准**——PM文档明确要求后续用视频标注数据在 2秒/3秒/5秒 之间比较事件级 Precision/Recall 和用户感知一致性，选出最优值（见 §4 第1项）。

### 3.2 核心输出字段

按 PM 文档 §8 统一字段命名，不要另起一套命名（避免跟下游接口/前端对不上）：

**事件级**：`event_id, pet_id, device_id, label_id, start_time, end_time, duration_sec, confidence, confidence_band(high/medium/low), signal_quality, wear_state(worn/off-body/charging/uncertain), model_version, algorithm_version, source, suppression_reason, user_feedback, local_day, timezone`

**日聚合**：`event_count, total_duration_sec, valid_wear_minutes, coverage_rate, baseline_delta_pct, trend_direction(up/stable/down/insufficient_data), night_ratio, data_quality_flag(good/partial/insufficient)`

**抓挠专属**：`scratch_event_count, scratch_total_duration_sec, scratch_duration_per_wear_hour, sleep_disruption_count, Baseline_scratch_event_count, Baseline_scratch_total_duration_sec, baseline_delta_pct, scratch_attention_level(C0/C1/C2)`

`confidence`/`data_quality_flag` 不参与打分计算，单独展示——数据不足时显示"佩戴不足/正在学习"，禁止用0代替无数据（PM文档 §15 明确要求）。

## 4. 待验证参数清单（算法工程侧的核心工作）

PM 文档里大量参数标注了"建议初始值""产品算法配置值，不是临床标准"，这些都需要拿真实标注数据验证/调整，而不是直接采信。按优先级排列，并给出用现有工具怎么验证：

| # | 参数 | 文档给的初始值 | 怎么验证 |
|---|---|---|---|
| 1 | 事件合并间隔 | 3秒（同类信号间隔≤3秒合并） | 用 `event_eval.py` + `run_review_bins_all_days.sh` 的 `MERGE_GAP` 参数分别跑 2s/3s/5s，比较事件级 Precision/Recall/F1e，选最优值。README 里现有说明"3s会把约一半真实事件错误合并"是基于1s场景的旧结论，这次要针对抓挠场景专门重新测 |
| 2 | 事件结束判定 | 连续>3秒未检测到抓挠 | 同上，与合并间隔一起联调，两者未必要用同一个数值 |
| 3 | 聚集阈值 | 1小时内≥5次抓挠事件记为1个聚集时段 | 需要先有一批多日标注数据，统计"聚集时段"出现频率是否合理（比如是否所有狗几乎每天都触发，或几乎没有狗触发——任一极端都说明阈值不合适） |
| 4 | 持续程度门槛 | 当日变化幅度≥10分才计入连续天数 | 依赖 #6 基线偏离分档是否合理，两者要联合验证 |
| 5 | 睡眠中断判定六项阈值 | 稳定睡眠≥5分钟、有效抓挠≥3秒、中止间隔≤30秒、清醒≥3分钟、合并间隔≤5分钟、夜间有效佩戴≥4小时 | 需要能可靠区分"睡眠/清醒/抓挠"三种状态的标注数据，是本方案里对数据要求最高的一块，建议先验证睡眠状态识别本身的准确率，再验证中断判定逻辑 |
| 6 | 基线偏离分档（双门槛表） | 见 §2.3 表格 | 先用现有多日数据跑一遍 `X_base`/`X_7d` 计算，看实际计算出来的偏离分布落在哪些档位，是否需要调整档位边界 |
| 7 | C0/C1/C2 总分边界 | 0-30 / 30-50 / 50-100 | 待上述子项都验证完、有真实评分分布后再定，不建议现在就锁死 |
| 8 | 红旗信号阈值 | 3倍基线、1分钟持续抓挠、≥3天持续偏离等 | 用历史确诊/复查记录（如果有）反推这些红旗阈值的误报率，没有确诊标签时先看触发频率是否合理 |

> 验证时注意 PM 文档 §13.2 的要求：训练集/验证集/测试集必须按犬只隔离，不能同一只狗跨集合。

### 4.1 合成数据已经发现的一个公式级问题（不是参数调优，是逻辑缺口）

用 `src/eval/gen_synthetic_scratch_scenarios.py` 跑合成数据时发现：**§2.3 双门槛公式里"分母最低按3计算"这条规则，会让低基线狗的适度绝对增加永远算不出分**。

具体机制：基线≈0的狗，分母被下限保护成3；要让 `ratio = current / 3 ≥ 1.3`（最低档"轻微变化"的倍数门槛），当天事件数必须 ≥4。也就是说，一只原本几乎不抓挠的狗，哪怕稳定维持在**每天3次**的新水平（`3/3=1.0倍`，达不到1.3倍门槛），无论持续多少天，变化幅度分永远是0——这正是我们最早讨论"前14天0、后14天3"那个例子的翻版，只是这次是在PM的正式公式里复现出来的，不是我们自己假设的。

这不是"参数取值需要调"的问题（调阈值治标不治本），而是双门槛公式本身对"极低基线+适度绝对增加"这类组合结构性不敏感。

**已采纳方案：分母保护值从3改成1**（`src/eval/scratch_burden.py` 里的 `BASELINE_DENOM_FLOOR`）。改动前后用9个既有场景+1个新增场景跑过完整回归，并单独做过边界值扫描（`baseline∈[0,10]步长0.5 × current∈[0,40]`覆盖次数维度、`baseline∈[0,10]秒 × current∈[0,1200]秒`覆盖时长维度）验证过：

- **改动只在一个极窄边界生效**：次数维度里，唯一被改变最终档位的组合是"基线中位数精确为0、当天事件数精确等于3"（0→3分从0分变成5分，即最初发现问题的那个案例本身）；时长维度里没有任何组合被改变（abs_min门槛是分钟级，2秒的floor差异在这个量级上完全可忽略）
- **PM文档7个worked examples（基线分别是2、2、2、5、5、30、30）全部不受影响**——这些基线都是≥2的整数，改动只在基线精确为0时才会让最终档位不同，跟PM验收过的例子没有重叠
- **一个需要记录的结构性副作用**：基线=0时，`ratio_min` 这道门槛会被 `abs_min` 自动带过（因为此时 `ratio≈current=abs_increase`，而每档的 `abs_min` 本身就比对应的 `ratio_min` 大得多），双门槛在基线=0这个特殊点上实际退化成了单门槛，只剩 `abs_min` 在把关。不算是新漏洞（`abs_min` 本身仍然独立、有效地挡住了1-2次这种真正微小的偶发增量），但这是本次改动引入的一个明确特性，值得在这里记录下来，避免以后有人以为双门槛在所有基线区间都同样生效
- **一个连带效应**：基线较低（比如=2）但非0的狗，ratio 计算变精确后，达到"基线偏离>3倍"红旗的时间点可能提前（合成数据里 `dog_gradual_worsening` 提前了3天触发），这是 ratio 算得更准确的自然结果，不是新引入的逻辑分支

结论：这个改动**没有**引入"1-2次抓挠靠倍数被放大成有分"的问题，`abs_min` 门槛在所有测试组合里都独立生效；也没有改变PM验收过的任何一个例子的最终档位。改动范围精确匹配 §4.1 最初描述的那个问题本身。

> 副带发现（跟本次改动无关，独立记一笔）：PM原文"示例六"（30→46）文字表述是20分，但按 §2.3 双门槛表字面计算（abs_increase=16≥5、ratio=1.53落在"1.5~2倍→10分"档）算出来是10分，两者对不上——这个疑点已确认跟"分母保护值"改动无关（baseline=30远大于任何floor取值，两个版本算出来的结果逐位相同），需要回头找产品侧核实原文口径，不在本次修复范围内。

### 4.2 用现有工具做同样的验证——不要止步于合成数据

上面这个发现是靠合成数据跑出来的，但合成数据只能验证"打分逻辑本身对不对"，不能替代真实数据验证。§4表格里那些参数（事件合并间隔、聚集阈值等）必须用真实标注数据+`event_eval.py`/`run_review_bins_all_days.sh` 验证，见 §8。

## 5. 验收标准（摘自 PM 文档 §12，抓挠相关部分）

| 指标 | 门槛 |
|---|---|
| 事件级 Precision（抓挠/甩头） | ≥90%（8月31日目标85%，10月13日目标95%，见文档 §4 标签表） |
| 事件级 Recall（抓挠/甩头） | ≥80% |
| 附加要求 | 高Precision优先；夜间和长毛犬需要单独出报告，不能只看整体平均 |

犬级宏平均（先按每只犬算指标再平均）是强制要求，避免数据量大的犬只主导整体指标。

## 6. 外部参考资料（作为参数校准的旁证，非设计主依据）

### Whistle FIT — [PMC10445133](https://pmc.ncbi.nlm.nih.gov/articles/PMC10445133/)

分级阈值（已用 Pruritus VAS 验证）：Infrequent 0–52秒/天、Occasional 53–119秒/天、Elevated 120–299秒/天、Severe >300秒/天（对应群体50/85/97分位）。这是目前能找到的、经过临床量表验证的绝对秒数参考，可以用来交叉检查 §4 里那些"次数/时长最小绝对增加"门槛（比如"≥3分钟/24h"这类值）在真实场景下是不是合理量级。

告警机制是"7天滚动均值所在分级，相比前一天上升≥1档触发"，比 PM 文档这套连续型评分更简单，但已经在7000+只狗、20个月的真实数据上验证过效果（告警上线后"4周内就诊"占比从35.2%升到54.1%，OR=1.63, p<0.0001，对既往无皮肤病记录的狗效果最明显）。如果后续验证发现 PM 这套更精细的评分体系在实际效果上并不比"简单分级+环比"更好，这是一个更简单的备选方案。

底层用 FilterNet 深度学习模型，与本项目 README 参考文献引用的一致。

### Vetrax — [What's Normal When It Comes To Scratching?](https://vetrax.com/whats-normal-when-it-comes-to-scratching/)

超过8万犬日的运营数据：日均抓挠约100秒，个体范围从<10秒到1500秒+。**样本可能有选择偏差**（用户本身可能因为担心皮肤问题才用监测设备）、"犬日"不等于独立犬只样本、原文未公开分位数和设备准确率——只能当粗略的量级参考，不能当临床阈值。核心价值是反复强调"What's normal for *this* dog"，支持 PM 文档"个人基线优先于群体均值"（§15 竞品对比一节也有同样表述）的设计方向。

### 7.2 合成数据覆盖的场景

| 场景 | 目的 |
|---|---|
| 低基线狗稳定波动 | 验证正常情况下不误报，全程应为 C0 |

### 7.3 结果摘要

除 §4.1 提到的低基线问题外，其余场景表现符合预期：
- 逐日恶化场景里能清楚看到 `delta_score` 逐日上升、`persistence_score` 在连续偏离≥3天后达到20分上限，并在偏离幅度超过3倍基线时正确触发 `baseline>3x` 红旗、总分跳到 C2
- 高基线小幅波动场景全程为0分，双门槛判断本身没问题（问题只出在基线接近0的边界情况）
- 聚集、长时间抓挠、缺失日这几个场景都按预期触发对应分项/标记
- **引导期绝对阈值兜底（§2.3.1）已实现并验证**：刚绑定设备就重度抓挠的场景，从第1天起（`bootstrap_mode=True`）就靠绝对阈值兜底触发 `total=60, tier=C2`；同期日常轻度抓挠的冷启动场景全程保持 C0，没有引入误报
- 夜间中断场景发现一个需要留意的边界情况：算法按 PM 文档 §5"事件按开始所在日期归属"的规则实现，跨零点的同一个"夜晚"会被切成两个日历日分别计算中断次数（比如23点和次日02点的两次抓挠会被算进两天），这是符合文档字面规则的行为，但实际是否符合"一晚的睡眠质量"这种产品语义，需要跟产品侧确认是否要改成按"睡眠周期"而不是"日历日"聚合夜间指标

## 9. 长期方向：分层贝叶斯模型（跟 §2 的PM公式并行探索，不是替换）

### 9.1 为什么

§2 那套 PM 定义的评分公式（四维度加权+红旗），权重和阈值都是经验值，不会随数据自动修正；§2.3 的"个人基线"和 §2.3.1 的"引导期兜底"之间是硬切换（21天），不是平滑过渡。这些问题的根本解法是**分层贝叶斯模型**（hierarchical Bayesian model）：

```
第1层（每天，第i只狗）：
  当天严重程度 ~ OrderedLogistic(alpha_i + beta·特征向量, cutpoints)
第2层（狗与狗之间）：
  alpha_i ~ Normal(0, sigma_alpha)   ← 个体基线，群体均值固定为0（原因见代码注释，
                                        避免跟cutpoints的位置互相抵消导致参数不可识别）
```

- `alpha_i`（个体基线）：数据多的狗主要由自己的数据决定，数据少的狗会被"收缩"（shrrink）往群体方向靠，这个过渡是模型自动算出来的，不需要写死"21天"这种硬边界
- `beta`（各特征的影响力）：从数据里拟合出来的，不是PM/我们自己拍的权重；可以用PM给的方向或Whistle FIT的阈值当**先验起点**，但会随真实标签数据自动修正，不是锁死的
- 新狗（零数据）：预测完全依赖群体层面的后验分布，效果上等价于现在的"引导期用Whistle阈值兜底"，区别是以后可以把这个"群体"换成我们自己客群的真实统计，而不是永远借用外部文献数字

详细讨论见对话记录；这不是要替换掉 §2 的PM公式（现在数据量下贝叶斯模型的后验基本被先验主导，短期内产出的判断不会跟现在的规则系统有本质区别），是要**现在就开始搭这套框架**，让它随着真实数据（更多狗、更多天、更多兽医标签）自动变得更准，不需要将来重新设计。

### 9.2 代码

- `src/eval/bayesian_skin_model.py`：模型定义（`fit_hierarchical_model`）+ 新狗预测（`predict_new_dog`，只用群体层面后验，不掺入个体信息）+ 结果汇总（`summarize`）。用 `PyMC` 实现（新增依赖：`pymc`、`arviz`，`requirements.txt` 还没加，先手动 `pip install pymc arviz`）
- `src/eval/validate_bayesian_skin_model.py`：合成数据验证脚本，4只"数据深度"不同的合成狗（60/20/5/30天历史），验证机制本身该有的统计行为，不是验证真实预测准不准

运行方式：
```bash
python src/eval/validate_bayesian_skin_model.py
```

### 9.3 合成数据验证结果

- **收敛正常**：r_hat≈1.0，0个发散样本，采样器本身没问题
- **✅ 数据量→不确定性的方向正确**：60天历史的狗，个体基线后验标准差(0.81)小于5天历史的狗(1.08)——数据越多，模型对这只狗的判断越有把握，符合预期，只是这次合成数据下差距不算悬殊
- **✅ 冷启动行为正确**：全新狗（零历史数据）的预测均值≈0（群体平均水平），标准差(1.77)明显大于任何一只有数据的狗——完全靠群体先验撑着，不会瞎猜出一个"看似精确"但没有依据的数字
- **⚠️ 绝对数值没有精确复现**：比如 `beta` 真实值0.8，估出来1.97——这是因为验证脚本生成合成标签用的是正态噪声，跟 `OrderedLogistic` 模型内部假设的逻辑分布噪声形式不完全匹配，导致尺度有系统性偏差。这次验证的目的是"机制方向对不对"，不是"合成DGP参数能不能精确复原"，这个偏差不代表模型实现有问题（收敛诊断已经排除了采样器本身的问题），真实数据接入后，模型拟合的是真实的似然形式，不存在这个DGP失配问题

### 9.3.1 多维特征验证——不是只用抓挠次数

`fit_hierarchical_model()` 的 `feature_cols` 本来就支持任意多个特征（`beta` 是按特征数量给的向量），第一版验证脚本为了讲解方便只用了一个"抓挠强度"，容易让人误以为模型只吃次数。后来补了5个特征重新跑：`event_count_z`（次数）、`duration_min_z`（总时长）、`night_ratio_z`（夜间占比）、`interval_std_z`（事件间隔的离散程度，代替"1小时≥5次"这种人为设的聚集阈值——间隔越集中数值越低，说明越聚集）、`sleep_interrupt`（是否中断睡眠），5个特征之间还刻意加了相关性（现实里次数多的日子通常时长也长、也更容易聚集，不是互相独立的干净数据）。

结果：收敛正常，5个特征的 `beta` **方向全部正确**（次数/时长/夜间占比/睡眠中断都是正向影响、间隔离散度是负向影响，这4类跟直觉都对得上）。数值大小的相对排序基本合理，但 `sleep_interrupt`（0/1二值特征）的排序比真实值靠后一些——二值特征天然比连续特征更难精确估计系数（信息量密度低，尤其数据量还很小的时候），这是需要留意但不算意外的现象，数据量上来后应该会改善。

## 10. 另一条路：直接对"抓挠计数"建模的三层贝叶斯模型（不需要兽医标签）

### 10.1 为什么单独开一节

§9 那版模型需要兽医打的有序标签（正常/关注/异常）才能训练，卡在标签数量和质量上。这里是另一种建模方式，**不需要任何兽医参与就能跑起来**：直接对"每天抓挠次数"这个IMU算出来的原始计数建模（负二项分布，处理"有的狗某几天特别多"这种过度离散），"个体基线"和"异常检测"都建立在这个计数模型上，兽医标签留到后面，只用来验证"统计上算异常的"是不是"真的有皮肤问题"——两件事解耦了，不用互相等。

两个模型定位不同，不是二选一：
- **§10 计数模型**：数据要求低（不需要标签），适合现在就跑起来做"个体基线+异常检测"的地基
- **§9 有序标签模型**：需要兽医标签，但产出的是直接对齐产品要展示的等级（C0/C1/C2），适合标签攒够之后拿来校准/验证

### 10.2 模型结构（品种→狗→每日，三层）

```
scratch_count[i] ~ NegativeBinomial(mu[i], alpha)
log(mu[i]) = mu_pop + breed_effect[breed[i]] + dog_effect[dog[i]]
breed_effect ~ Normal(0, sigma_breed)   ← 非中心化参数化，见代码注释
dog_effect   ~ Normal(breed_effect[该狗品种], sigma_dog)
```

用**非中心化参数化**（`effect_raw ~ Normal(0,1)` 再乘以 `sigma`，不是直接从 `Normal(mu,sigma)` 采样）——这是PyMC分层模型的标准做法，避免"漏斗"病态几何导致采样效率差、容易发散，比 §9 那版模型的参数化方式更规范。

品种层用的是我们影棚实际的4个品种：**金毛（大型）、中华田园犬（中型）、比熊（小型）、马尔济斯（小型）**，大中小体型都覆盖到了。

### 10.3 代码

- `src/eval/bhm_scratch_count.py`：模型定义（`fit_model`）+ 异常检测（`posterior_predictive_check`，用只基于基线期数据估出的个体后验，模拟"正常情况下应该是多少次"的预测分布，看新观测值落在第几百分位，超过97.5%或低于2.5%判定异常——是有统计意义的检验，不是"倍数超过3"这种手调阈值）+ 冷启动近似（`sequential_cold_start`，用Gamma-Poisson共轭近似做在线更新，不需要每天重跑完整MCMC）
- `src/eval/validate_bhm_scratch_count.py`：合成数据验证，用我们实际的4个品种，每个品种额外配了9只"合成陪跑"狗凑够验证用的样本规模（现实里每个品种现在只有1只真实狗，组内方差没法估，合成陪跑狗只是为了在统计上说得过去的规模下验证机制本身，不代表我们真的有这么多狗）

运行方式：
```bash
python src/eval/validate_bhm_scratch_count.py
```

### 10.4 合成数据验证结果

三件事都验证过：

- **收敛正常**：r_hat=1.000，0发散样本
- **部分池化方向正确**：比如 `real_金毛_0`（对应我们实际那只金毛的占位符）19天基线期原始均值2.79，模型估计成3.25，被同品种其他狗的数据拉了一把；`syn_金毛_1` 原始均值9.21（明显偏高），模型估计8.40，同样被适度拉向品种均值
