# 皮肤健康评估（基于抓挠行为）方案（草案）

## 背景与目标

现有 pipeline（`infer_csv_scratch.py`）已经能从 IMU 数据里识别出"抓挠"这一行为片段（起止时间、置信度）。这份文档讨论下一步：把离散的抓挠事件流，转成对皮肤健康有参考意义的信号。

真实场景下没有大量"皮肤病/健康"标签数据，很难一上来就做监督分类。方案分两部分独立推进：

1. **趋势报告**：把抓挠事件聚合成日/周趋势，先让人（主人/兽医）能看出变化，不需要额外建模
2. **异常检测**：在趋势基础上，自动标记"较个体基线明显上升"的时段，减少人工盯盘成本

两部分互相独立，趋势报告可以先做，异常检测在有了趋势数据后随时能接上。

---

## 第一部分：抓挠事件趋势报告

### 1.1 数据来源

`infer_csv_scratch.py` 或 `run_review_bins_all_days.sh` 跑出来的 `*_infer.json`，每条抓挠片段目前已有：

- 起止时间（绝对时间戳）
- `conf_max` / `conf_mean`（置信度）
- 片段时长

### 1.2 需要新增的特征（可选，取决于IMU能否支撑）

| 特征 | 用途 | 可行性 |
|---|---|---|
| 加速度峰值/RMS | 抓挠强度，力度大可能提示更严重的瘙痒 | 现有数据直接可算，不需要新模型 |
| 抓挠部位（头部/耳朵 vs 身体/后腿） | 不同部位对应不同皮肤问题（耳螨 vs 跳蚤/过敏性皮炎等） | 需要验证项圈朝向数据是否能区分头部甩动 vs 身体抓挠的运动模式，可能需要额外标注一批"挠耳朵"vs"挠身体"样本单独训练一个细分类器，短期先不做，作为迭代方向 |
| 昼夜分布 | 夜间抓挠增多是常见的皮炎/过敏恶化信号 | 现有时间戳直接可算 |

### 1.3 聚合与展示

按 **天** 聚合出：

```
日期 | 抓挠次数 | 总时长(s) | 平均强度 | 夜间占比(22:00-6:00)
```

按 **周** 再聚合一次，方便看长期趋势。

初期用一个脚本（例如 `src/eval/scratch_trend.py`）读取一段时间内所有 `*_infer.json`，输出：

- CSV/表格（供后续异常检测消费）
- 简单趋势图（折线图：每日次数/时长；可以先用 matplotlib 出图，不需要做成 web dashboard）

**MVP 范围**：先出CSV+静态图，不做实时dashboard——数据量和使用频率还不确定要不要投入前端。

## 第二部分：异常检测（个体基线偏离）

### 2.1 思路

不做"健康/不健康"二分类，而是回答"这只狗最近抓得比自己平时明显多/少吗"。

原因：
- 没有监督标签，做不了真正的疾病分类
- 每只狗的"正常"抓挠水平本身差异很大（品种、毛发、性格），跨狗的绝对阈值没有意义，只有跟自己历史比才有意义

### 2.2 方法（由简到繁，按需要升级）

| 方法 | 说明 | 何时用 |
|---|---|---|
| 滑动基线 + Z-score | 用过去N天（如14天）的均值+标准差算基线，当天值超过 baseline + kσ 标记异常 | 起步方案，实现成本最低，可解释性最好 |
| EWMA 控制图 | 给近期数据更高权重，对趋势性上升比固定窗口Z-score更敏感 | 如果Z-score对"缓慢恶化"不够敏感时升级 |
| Change-point detection（如 `ruptures` 库） | 检测时间序列里统计特性突变的分割点，不需要预设窗口长度 | 想自动发现"从哪天开始恶化"这种转折点时用 |

**建议起步用 Z-score / 滑动基线**：足够简单、能立刻用现有数据跑起来，且异常判断逻辑对使用者（主人/兽医）容易解释（"这周抓挠次数比平时高2个标准差"），比黑盒模型更容易建立信任。

### 2.3 输出

对每只狗每天，输出：

```
日期 | 当日指标 | 基线均值 | 基线标准差 | 偏离(σ) | 是否异常
```

异常触发时可以额外把当天/当周对应的抓挠片段列出来（复用 `run_review_bins_all_days.sh` 的视频裁剪能力），方便直接去看是不是真实恶化还是误报。

### 2.4 后续升级路径（数据积累后）

一旦通过异常检测+人工复查/兽医诊断积累了一批"确诊时间段"标签，可以：

- 把"确诊窗口"作为弱标签，回过头验证异常检测的召回率/误报率，调整 kσ 阈值
- 数据量够大后，再考虑有监督模型（比如输入近N天趋势特征，预测"是否需要就医"），但这是远期方向，不在当前范围内

## 开放问题（需要确认/讨论）

1. 抓挠部位细分是否有价值——需要先确认现有IMU数据能否区分挠耳朵/挠身体的运动模式，还是需要额外采集标注数据
2. 趋势报告要不要做成可交互dashboard，还是先出CSV+静态图就够用
3. 异常检测的基线窗口长度（14天？30天？）和阈值（2σ？3σ？）需要拿真实多日数据试出合理值，目前是经验值待验证
4. 有没有可用的"确诊"标签来源（兽医记录/主人反馈），有的话异常检测的效果验证会快很多
