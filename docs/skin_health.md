# 皮肤健康评估（基于抓挠行为）方案（草案）

## 背景与目标

现有 pipeline（`infer_csv_scratch.py`）已经能从 IMU 数据里识别出"抓挠"这一行为片段（起止时间、置信度）。这份文档讨论下一步：把离散的抓挠事件流，转成对皮肤健康有参考意义的信号。

真实场景下没有大量"皮肤病/健康"标签数据，很难一上来就做监督分类。方案分三部分独立推进：

1. **趋势报告**：把抓挠事件聚合成日/周趋势，先让人（主人/兽医）能看出变化，不需要额外建模
2. **Scratch Burden Score（SBS，抓挠负担分）**：把当天的抓挠行为综合成一个 0–100 的绝对负担分，量化"今天抓得有多重"
3. **基线偏离信号**：与 SBS 并行的独立信号，专门回答"较这只狗自己的历史相比，是否发生了有意义的变化"——不是 SBS 的子项，而是单独展示的第二路信号（原因见 §3.4）

三部分互相独立、可以分开落地，趋势报告可以先做；SBS 和基线偏离信号建议同时设计（两者共享同一批底层特征），但作为两条并行输出，不要合并成一个数字。

---

## 第一部分：抓挠事件趋势报告

### 1.1 数据来源

`infer_csv_scratch.py` 或 `run_review_bins_all_days.sh` 跑出来的 `*_infer.json`，每条抓挠片段目前已有：

- 起止时间（绝对时间戳）
- `conf_max` / `conf_mean`（置信度）
- 片段时长

### 1.2 需要新增的特征（可选，取决于IMU能否支撑）

| 特征 | 用途 | 可行性 |
|---|---|---|
| 加速度峰值/RMS | 抓挠强度，力度大可能提示更严重的瘙痒 | 现有数据直接可算，不需要新模型 |
| 抓挠部位（头部/耳朵 vs 身体/后腿） | 不同部位对应不同皮肤问题（耳螨 vs 跳蚤/过敏性皮炎等） | 需要验证项圈朝向数据是否能区分头部甩动 vs 身体抓挠的运动模式，可能需要额外标注一批"挠耳朵"vs"挠身体"样本单独训练一个细分类器，短期先不做，作为迭代方向 |
| 昼夜分布 | 夜间抓挠增多是常见的皮炎/过敏恶化信号 | 现有时间戳直接可算 |

### 1.3 聚合与展示

按 **天** 聚合出：

```
日期 | 抓挠次数 | 总时长(s) | 平均强度 | 夜间占比(22:00-6:00)
```

按 **周** 再聚合一次，方便看长期趋势。

初期用一个脚本（例如 `src/eval/scratch_trend.py`）读取一段时间内所有 `*_infer.json`，输出：

- CSV/表格（供后续异常检测消费）
- 简单趋势图（折线图：每日次数/时长；可以先用 matplotlib 出图，不需要做成 web dashboard）

**MVP 范围**：先出CSV+静态图，不做实时dashboard——数据量和使用频率还不确定要不要投入前端。

## 第二部分：Scratch Burden Score（SBS，抓挠负担分）

### 2.1 定位

SBS 是 0–100 的连续指标，衡量"今天的抓挠行为对宠物造成的综合负担有多重"。

**重要定位**：这是行为监测/护理管理指标，**不是**疾病诊断分，不直接等同于皮肤病严重程度。分数等级也不用"Disease severity / High risk / Medical alert"这类医疗化措辞，只用"Within usual range / Slight increase / Watch closely / Increased scratching / Significant increase"这种行为描述。

### 2.2 底层行为定义

在聚合成分数之前，先要在事件层面做清晰定义，避免"传感器把一次连续抓挠切成好几个动作"污染统计：

| 概念 | 定义 |
|---|---|
| 抓挠动作（stroke） | 一次前/后肢接触身体并完成的一个往复抓动周期，算法识别的最小单元，**不直接展示给用户** |
| 抓挠事件（event/bout） | 连续 ≥2 个抓挠动作、动作间隔 ≤2 秒；连续 5 秒无新动作则事件结束；事件总时长 ≥1.5 秒才计入；需排除普通走动抖动、甩水、全身抖动等低置信度/非抓挠动作 |
| 有效佩戴时间（valid wear time） | 当天设备正确佩戴且数据质量达标的累计时长；建议全天 ≥12 小时才生成正式日分，佩戴不足显示"数据不足"而不是直接判定负担低 |

这一层可以直接在现有 `infer_csv_scratch.py` 的输出基础上加一层事件合并逻辑（`--merge_gap` 已经在做类似的事，可以复用/对齐这里的 2 秒/5 秒阈值定义，不用重新发明）。

### 2.3 核心公式

```
SBS_d = 100 × round(clip(
    0.30 × F_d      # 抓挠频率负担
  + 0.30 × D_d      # 抓挠总时长负担
  + 0.15 × P_d      # 单次持续性/长事件负担
  + 0.15 × N_d      # 夜间及睡眠干扰负担
  + 0.10 × B_d       # 相对个体基线的变化
, 0, 1))
```

各子项（`H_d` = 当天有效佩戴小时数）：

- **频率负担** `F_d`：事件率 `ER_d = E_d / H_d`（每小时事件数），对数归一化 `F_d = clip(ln(1+ER_d) / ln(1+ER_high), 0, 1)`，一期 `ER_high = 4次/小时`
- **时长负担** `D_d`：时长率 `DR_d = T_d / H_d`（每小时抓挠秒数），同样对数归一化，一期 `DR_high = 60秒/小时`
- **持续性负担** `P_d`：当天事件时长的 P90 值 `L_90,d`，`P_d = clip((L_90,d − L_normal) / (L_high − L_normal), 0, 1)`，一期 `L_normal=3秒, L_high=20秒`。用 P90 而不是最长一次是为了降低单个极端事件的影响
- **夜间/睡眠干扰负担** `N_d = 0.6 × clip(T_sleep/120, 0,1) + 0.4 × clip(I_sleep/6, 0,1)`：主睡眠期间抓挠时长 + 抓挠导致的睡眠中断次数（后者依赖设备能否可靠识别"因抓挠而醒来"，做不到就先只算睡眠期抓挠时长）
- **基线变化** `B_d`：见 §2.4

对数归一化是为了避免个别极端高频事件把分数无限拉高；用"每小时"而不是"当天总数"是为了消除佩戴时长不同带来的偏差（这点跟第一部分趋势报告的聚合逻辑是一致的，两边应该共享同一套按小时归一化的底层特征）。

**分数等级**：0–19 Low / 20–39 Mild / 40–59 Moderate / 60–79 High / 80–100 Very High，对外只用行为描述性文案，不用医疗化措辞。

### 2.4 基线变化 `B_d`（关键设计：如何避免"基线自我治愈"）

先算每日综合指标 `X_d = 0.5F_d + 0.5D_d`，再算个体基线：

```
X_base = median(X_{d-21}, ..., X_{d-8})   # 用第8~21天前的14天数据，取中位数
```

**关键点：基线窗口刻意跳过最近 7 天**，不让近期（可能正在恶化的）数据污染基线——这正是应对我们之前讨论过的"滚动窗口基线会在一个窗口长度内把持续性异常学习成新常态、导致警报自愈消失"问题的解法。

再用近 7 天加权均值 `X_7d`（越近权重越高）跟基线比：

```
Δ_d = (X_7d − X_base) / max(X_base, ε)
B_d = clip(Δ_d / 2, 0, 1)   # 较基线上升100% → B_d=0.5；上升200%+ → B_d=1
```

刚绑定设备、基线不足 7 天有效数据时 `B_d = 0` 并标注"基线正在建立中"，不用群体平均值强行替代（体型/品种/年龄差异太大，硬替代容易误判）。

## 第三部分：基线偏离——为什么要独立于 SBS 展示

### 3.1 SBS 里 `B_d` 权重只有 10% 的问题

SBS 的 60% 权重（`F_d + D_d`）绑定在**绝对**阈值上（`ER_high=4次/小时`、`DR_high=60秒/小时`）。这意味着：一只本身抓挠基线很低的狗（比如从几乎不抓变成偶尔抓几次），事件率可能仍然远低于 `ER_high`，`F_d`、`D_d` 贴地，哪怕 `B_d` 因为相对基线翻倍而拉满（=1），10% 权重也只贡献 10 分，SBS 总分大概率还停留在 Low 档——**一个有临床意义的相对变化，可能永远越不过这套绝对阈值主导的评分体系**。

Vetrax 的真实群体数据也印证了这一点（见 §5 参考资料）：狗群体日均抓挠时长约100秒，但个体差异极大——少的狗一天不到10秒，多的狗能到1500秒以上，150倍量级的跨狗差异。**但这个数字本身有明显的样本偏差**（见 §5 详细说明：Vetrax 用户很可能本身就是为监测皮肤问题而使用设备，"8万犬日"也不等于8万只独立犬只样本），只能当作粗粒度的行业观察值，不能当成临床正常阈值。这进一步说明任何一套跨狗通用的绝对阈值（包括本方案的 `ER_high`/`DR_high`）天然只能是粗粒度的群体参考，真正有判断力的还是个体基线，支持"基线偏离要独立展示、不能被绝对阈值主导的SBS稀释掉"这个设计决策。

这正好对应我们之前讨论的"前14天都是0、后14天都是3"的场景：换算成事件率远低于绝对阈值，纯靠 SBS 主分不会报警。

### 3.1.1 一个更可信的校准锚点：Whistle FIT 的分级阈值（已用 Pruritus VAS 验证）

比 Vetrax 的粗略均值更值得参考的，是 Whistle FIT（见 §5 PMC10445133）实际生产系统用的抓挠/舔舐分级阈值——这套阈值经过与兽医使用的 Pruritus 视觉模拟量表（Pruritus Visual Analogue Scale）比对验证过，不是拍脑袋定的：

| 等级 | 抓挠（7天滚动日均） | 群体分位数 | 舔舐（7天滚动日均） |
|---|---|---|---|
| Infrequent | 0–52 秒/天 | 低于50%的狗 | 0–7 分钟/天 |
| Occasional | 53–119 秒/天 | 高于50%的狗 | 7–19 分钟/天 |
| Elevated | 120–299 秒/天 | 高于85%的狗 | 19–43 分钟/天 |
| Severe | >300 秒/天 | 高于97%的狗 | >43 分钟/天 |

这套数据对本方案有直接校准价值：
- 换算成"每小时"量级（按每天约16~20小时有效佩戴估算），Elevated 门槛（120秒/天）大约对应 6~7.5秒/小时——**远低于本方案 `DR_high=60秒/小时` 这个经验值**，说明我们之前设的绝对阈值可能定得偏高（更接近"Severe 都远远打不到"的水平），需要重新校准，或者至少要说明清楚 SBS 的 `DR_high` 和 Whistle 的分级口径不是同一个东西（Whistle 是"7天滚动日均秒数"，本方案 `DR_d` 是"当天每小时秒数"，两者归一化基准不同，直接套用前必须先统一单位）
- Whistle 用的是**离散分级 + 环比变化触发告警**，而不是本方案的连续 0–100 分：告警规则是"7天滚动平均的等级，相比前一天上升了至少一个档位就触发"（比如从 Infrequent 升到 Occasional），且要求过去7天里至少有3.5天的有效数据、设备刚绑定的前7天不产生告警（最早第9天才可能出第一次告警）。这是一种更简单、可解释性更强的"基线偏离"实现方式，可以作为附录 §4 方法里 `B_d`/Z-score/EWMA 之外的第四个候选——**而且这套简化设计已经在超过7000只狗、20个月的真实数据上验证过确实有效**（见下方 §3.1.2）

### 3.1.2 真实世界效果验证（PMC10445133 的实证数据，不只是摘要）

这篇论文用 Banfield 兽医连锁1,042家门店的电子病历 + Whistle FIT 数据，对比"告警上线前10个月 vs 告警上线后10个月"，7000+只狗、20个月：

- **告警确实推动了更多就医**：告警后4周内产生的"告警就诊"占比从 35.2%（上线前）升到 54.1%（上线后），优势比 OR=1.63（95% CI 1.57–1.69, p<0.0001），在所有抓挠/舔舐等级下都成立
- **对"之前从没因皮肤问题就诊过"的狗（Group 0）效果最明显**：这组狗在告警上线后处方药物数量从894（前10个月）跳到3921（后10个月）——说明这套系统主要价值在于帮那些主人平时没意识到问题的狗更早被发现，而不是给已经在治疗的狗加戏
- **告警文案不含强制性话术**，只是客观陈述"XX最近抓挠更多了，抓挠等级升到了YY，去看看健康报告"，用户看报告时才会看到"Elevated/Severe 建议预约兽医检查"这类建议——这个"先给数据、让用户自己决定要不要行动"的克制设计，跟本方案"不用医疗化措辞、只用行为描述性文案"（见 §2.3 分数等级）的思路是一致的

这组数据是"告警系统真的有用"这个假设目前能找到的最有力的真实世界证据，值得作为本项目立项/汇报时的支撑材料，而不只是设计参考。

### 3.2 解决方式：两路信号并行输出，不合并成一个数字

- **SBS**：回答"今天绝对负担有多重"——给主人/兽医一个当天严重程度的直觉
- **基线偏离信号**：回答"较这只狗自己的历史相比，是否发生了有意义的变化"——独立展示，不折算进 SBS 总分

基线偏离信号可以直接复用 `B_d` / `Δ_d` 的计算，或者用之前讨论的 Z-score / EWMA / change-point 方案：

| 方法 | 说明 | 适用 |
|---|---|---|
| `B_d`/`Δ_d`（本方案） | 基线窗口跳过最近7天，天然规避自我治愈问题 | 默认起步方案，跟 SBS 共享特征，实现成本最低 |
| Whistle FIT 式离散分级+环比升级 | 7天滚动均值落入哪个分级（见 §3.1.1 四档表），相比前一天分级上升就触发；要求过去7天≥3.5天有效数据，绑定设备后7天内不触发 | 想要更简单、可解释性更强、且已有真实世界验证效果的方案时可以直接参考这套规则，不一定要自己设计连续型指标 |
| 滑动 Z-score / EWMA | 见附录 §4 | 需要标准差/控制限这种统计显著性表达时用 |
| Change-point detection（`ruptures`） | 离线批量分析一段历史，自动找出"从哪天开始变的"分割点 | 回溯分析用，不是逐日报警工具 |

展示形式类似：`SBS = 18 (Low)，但较基线上升 120%，建议关注`——两个数字同时给，不让其中一个掩盖另一个。

### 3.3 输出字段

不管走哪条路径，后台都应该保留可解释的中间字段，而不是只吐一个总分：

```
scratch_burden_score, scratch_event_count, scratch_total_duration_sec,
scratch_event_rate_per_hour, scratch_duration_rate_per_hour,
scratch_event_duration_p90_sec, sleep_scratch_count, sleep_scratch_duration_sec,
sleep_interrupt_count, baseline_change_percent, valid_wear_time_hours,
algorithm_confidence, data_completeness, score_version
```

`algorithm_confidence`（识别置信度）和 `data_completeness`（当天有效数据覆盖度）**不参与打分计算**，单独展示——否则识别质量差的时候反而会算出一个虚假的低分。置信度/覆盖度不足时直接显示"数据不足，无法计算今日抓挠负担"，而不是给一个看似正常的低分。`score_version`（如 `SBS_v1.0`）用于后续调参后的可追溯。

### 3.4 后续升级路径（数据积累后）

一旦通过 SBS + 基线偏离信号 + 人工复查/兽医诊断积累了一批"确诊时间段"标签，可以：

- 把"确诊窗口"作为弱标签，回过头验证两路信号各自的召回率/误报率，重新校准权重（0.30/0.30/0.15/0.15/0.10 目前是经验值）和阈值（`ER_high`/`DR_high`/`L_high`/`T_sleep,high` 等）
- 数据量够大后，再考虑有监督模型，但这是远期方向，不在当前范围内

## 附录：基线偏离的备选统计方法

| 方法 | 说明 | 何时用 |
|---|---|---|
| 滑动基线 + Z-score | 用过去N天（如14天）的均值+标准差算基线，当天值超过 baseline + kσ 标记异常 | 简单、可解释性好，但若基线窗口连续滚动（含近期数据），持续性异常会在约一个窗口长度后被"学习"成新常态而停止报警——本方案 §2.4 用"跳过最近7天"规避了这个问题，若用纯 Z-score 也要采用同样的跳过窗口设计 |
| EWMA 控制图 | 给近期数据更高权重的移动均值，配合控制限判异常 | 对"缓慢恶化"比固定窗口Z-score更敏感；同样要注意基线是否持续被新数据更新的问题 |
| Change-point detection（`ruptures`） | 检测时间序列里统计特性突变的分割点，不需要预设窗口长度，能回溯"大概从哪天开始恶化" | 离线批量分析用，适合复查历史数据/给兽医参考，不是逐日自动报警的天然形态 |

## 5. 外部参考资料

### Vetrax — What's Normal When It Comes To Scratching?

[原文链接](https://vetrax.com/whats-normal-when-it-comes-to-scratching/)。基于超过8万个"犬日"（dog-days）的运营数据观察：不同年龄/品种/性别混合计算，日均抓挠约100秒，个体范围从不足10秒到1500秒以上。

**使用时必须带上的限制**：
- 样本可能有选择偏差——愿意用这类监测设备的主人，很可能本身就是因为担心皮肤/瘙痒问题才买的，样本不等于"健康犬群体"
- "8万犬日"不是8万只独立犬只（比如1000只狗连续戴80天也是8万犬日），数据独立性存疑
- 原文没有公开实际犬只数、健康/患病犬比例、犬种细分、中位数/标准差/分位数、设备识别准确率——只能当一个粗略的行业观察值，**不能**当作临床正常范围的判断依据

**结论**：这篇文章的真正价值不是"100秒"这个数字本身，而是它反复强调的"What's normal for *this* dog"——支持本方案"个体基线为主、群体数据只做粗粒度参照、犬种只作为未来的校正变量而非固定阈值"的设计方向（见 §3.1）。

### Response of pet owners to Whistle FIT® digital alerts of increased pruritic activity in their dogs — PMC10445133

[原文链接](https://pmc.ncbi.nlm.nih.gov/articles/PMC10445133/)。Zoetis + Kinship（Whistle 母公司）的回顾性研究，Frontiers in Veterinary Science 发表，同行评审、方法公开、样本量大（7000+只狗、20个月、1042家 Banfield 门店电子病历比对），可信度明显高于 Vetrax 那篇博客文章。

- **分级阈值已用 Pruritus VAS 验证**（见 §3.1.1 详细表格），可以作为 SBS 绝对阈值校准的可信锚点，比 Vetrax 的粗略均值靠谱得多
- **告警机制**：7天滚动均值所在分级，相比前一天上升≥1档就触发；要求过去7天≥3.5天有效数据；设备绑定后前7天不触发（最早第9天出第一次告警）——是一套已经跑通、比本方案 `B_d` 更简单的基线偏离实现（见 §3.2 方法对比表）
- **真实世界效果**：告警上线后"告警4周内就诊"占比从35.2%升到54.1%（OR=1.63, 95% CI 1.57–1.69, p<0.0001），对既往没有皮肤病就诊记录的狗效果最明显（见 §3.1.2）——是"告警系统真的能推动干预行为"这个假设目前最有力的真实世界证据
- 底层用的 FilterNet 深度学习模型，与本项目 README 参考文献里已引用的 FilterNet 论文/仓库是同一血统，说明"IMU抓挠识别→瘙痒告警"这条路径已有规模化商用先例，不是凭空设计

## 开放问题（需要确认/讨论）

1. 抓挠部位细分是否有价值——需要先确认现有IMU数据能否区分挠耳朵/挠身体的运动模式，还是需要额外采集标注数据
2. 趋势报告要不要做成可交互dashboard，还是先出CSV+静态图就够用
3. SBS 各阈值需要重新校准：`DR_high=60秒/小时` 这个经验值明显偏高（Whistle 的 Elevated 门槛换算下来只有约6~7.5秒/小时，见 §3.1.1），下一步应该先把 `F_d`/`D_d` 的归一化基准统一成 Whistle 同款"7天滚动日均"口径，再拿真实数据校准，而不是继续用"当天每小时"这套自定义单位；`ER_high`/`L_normal`/`L_high`/`T_sleep,high`/`I_high` 以及权重（0.30/0.30/0.15/0.15/0.10）也都还是经验值，待真实多日数据 + 不同品种/体型样本验证
4. 睡眠中断识别（`I_sleep`）依赖设备能否可靠判断"因抓挠而醒来"，需要先验证现有IMU数据能不能支撑这个判断，做不到的话 `N_d` 先退化成只算睡眠期抓挠时长
5. 有没有可用的"确诊"标签来源（兽医记录/主人反馈），有的话两路信号的效果验证会快很多
6. 基线偏离信号要不要直接照搬 Whistle 的"离散分级+环比升级"规则（§3.1.1/§3.2），而不是自研 `B_d`/`Δ_d`——前者实现更简单、且已有7000+只狗的真实世界验证效果（§3.1.2），后者理论上更精细但目前完全没有验证过，需要权衡"自研的精细度"和"抄作业的确定性"哪个对当前阶段更划算
7. 告警系统上线后的效果指标，除了算法准确率，还应该追踪"是否真的推动了就医/干预行为"这类业务层面指标（PMC10445133 §3.1.2 是现成的评估方法参考）
