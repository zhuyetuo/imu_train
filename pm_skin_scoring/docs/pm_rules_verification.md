## 二、S值（综合严重度，问答部分权重60%）

**结论：`pm_skin_scoring/code/questionnaire_app.py`已按下面公式实现，
用PM文档给出的满分示例(74.25分)做过精确验证。**

```
S总分 = C值(0-100) × 40%
      + 皮肤状态组原始分小计(皮肤颜色+体味+皮损) × 35%
      + 毛发状态组原始分小计(秃毛部位+秃毛面积+整体毛质) × 25%
```

组内原始分直接相加，不做归一化处理，再乘以组权重——这个是跟用户
确认过的公式形式（见对话记录），不是自己猜的。

**验证用例**（PM文档原文"总分74.25分=100×0.4+55×0.35+60×0.25"）：

```python
compute_score(
    c_value=100, has_hair_loss="是",
    color="C. 明显鲜红，但还没有破皮。",              # 15分（皮肤颜色单项最高分，不是满分表里的20——PM这题满分就是15）
    odor="D. 一进屋或者离得很远，就能闻到恶臭。",       # 20分
    lesion="D. 有糜烂、液体、结痂、脓包、红疙瘩，或者皮肤裂开。",  # 20分
    hair_spot="D. 脱毛连成一大片，不是零星小块。",      # 20分
    hair_diameter="D. 最大的一块超过3cm，面积比较明显。", # 20分
    coat="D. 大部分毛发都明显干枯、易断、毛质很差。",    # 20分
)
# 皮肤组=15+20+20=55（跟PM举例的55完全对上）
# 毛发组=20+20+20=60（跟PM举例的60完全对上）
# S总分 = 100*0.4 + 55*0.35 + 60*0.25 = 40 + 19.25 + 15 = 74.25
# 实测输出: 74.25 ✅ 精确匹配，不是近似值
```

## 三、发现并修复的问题：Python内置round()的银行家舍入

第一版实现用`round(total, 1)`，`round(74.25, 1)`在Python里实际算出
`74.2`（不是`74.25`四舍五入后的`74.3`），因为Python的`round()`是
round-half-to-even（银行家舍入），不是标准四舍五入——这跟
`skin_health/docs/rf_synthetic_validation_findings.md`里记录过的同一个
坑完全一样（那边是合成数据标签生成踩过的），这次在S值计算这里又踩了
一次，说明这是个值得记住的通用陷阱，不是偶然。

修复：用`_round_half_up()`（`math.floor(x*10**n+0.5)/10**n`）代替
Python内置`round()`，验证`_round_half_up(74.25, 2)`精确等于`74.25`，
不再丢失/错误舍入这个精度。同时把S总分的显示精度从1位小数改成2位
小数——1位小数本身就会丢失PM文档举例里"74.25"这种精确到分的数字。
